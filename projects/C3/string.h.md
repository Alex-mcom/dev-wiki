## `memchr()`

`void *memchr(const void *str, int c, size_t n)`

Ищет первый байт, равный `(unsigned char)c`, среди первых `n` байт.

**Возврат:** указатель на найденный байт или `NULL`.

**Особенности:**
    - `\0` не является концом, область может быть вообще не строкой.
    - При `n == 0` возвращается `NULL`.
    - Просматривается ровно `n` байт, читать дальше нельзя.

**Реализация:**
    1. Привести `c` к `unsigned char`.
    2. Байтами дойти до границы слова.
    3. Пока осталось не меньше `sizeof(size_t)` байт, проверять слово: `HASZERO(w ^ (ONES * c))`.
    4. Добить хвост и точное место внутри слова найти байтовым циклом.

**Ошибки:** забыть привести `c`, выйти за `n` в цикле, вернуть позицию слова вместо позиции байта.

```c
const char s[] = "hello\0world";  // sizeof = 12, внутри есть \0

memchr(s, 'o', 11);   // s + 4
memchr(s, 'w', 11);   // s + 6, \0 в середине поиск не останавливает
memchr(s, 'l', 2);    // NULL, просмотрены только "he"
memchr(s, 'x', 11);   // NULL
memchr(s, 'h', 0);    // NULL, n == 0
memchr(s, 'h' + 256, 11);  // s + 0, c приводится к unsigned char
```


### Оптимизация `Word-at-a-time`

Вместо того чтобы читать и сравнивать по одному байту за раз (что медленно), код читает сразу `sizeof(size_t)` байт (обычно 8 байт на 64-битных системах) за одну инструкцию процессора.

Процессор не умеет за одну инструкцию искать байт в 64-битном числе. Но мы можем «притвориться», что 64-битный регистр — это массив из 8 независимых 8-битных чисел, и применить к ним битовую математику:

- `k = ONES * c` — «размножает» искомый байт `c` по всем 8 байтам слова. (Например, если ищем `'A'` (0x41), то `k` станет `0x4141414141414141`).
- `*w ^ k` — делает XOR. Если байт в памяти совпадает с искомым, результат в этом байте будет `0x00`.
- `HASZERO(...)` — трюк, который за 4 операции (`-`, `&`, `~`, `&`) проверяет, есть ли хотя бы один нулевой байт во всем 64-битном слове. (Тот самый трюк с `ONES` и `HIGHS`).


#### Выравнивание (Alignment)

Строка `for (; ((uintptr_t)s & ALIGN) && n && *s != c; s++, n--);` — это оптимизация под названием **Alignment Peeling** (или Head alignment). 

Процессор читает машинные слова по адресам, кратным их размеру, намного быстрее (а на некоторых архитектурах, например ARM, чтение по невыровненному адресу вообще вызывает аппаратное исключение — Segmentation Fault). Поэтому этот цикл сначала побайтово «съедает» начало строки, пока указатель не выровняется до границы 8 байт.


#### SWAR

**Байт (8 бит)**

Возьмем `0xA5` (в десятичной это 165)

```c
Номер бита:    7    6    5    4    3    2    1    0
Двоичное:      1    0    1    0    0    1    0    1
Вес (2^n):   128   64   32   16    8    4    2    1
             (0x80)                            (0x01)
               ^                                ^
            Старший                          Младший
            бит (MSB)                        бит (LSB)
```


**Машинное слово (64 бита / 8 байт)**

Теперь объединим 8 байт в одно 64-битное слово (например, `size_t` или `uint64_t`).

```c
Байт №:        7        6        5        4        3        2        1        0
Биты:      [63..56] [55..48] [47..40] [39..32] [31..24] [23..16] [15..8]  [7..0]
Ранг:       ^                                                            ^
          Старший                                                      Младший
          байт (MSB)                                                   байт (LSB)
```

**Little Endian**

В x86 и ARM (Little Endian) **младший байт (Байт 0) лежит по младшему адресу памяти**.

**Физическое представление в памяти (x86 / Little Endian):**

```c
Адрес:      Адрес + 0         Адрес + 1
Данные:       0x00              0x41
Какой байт:  Младший (Байт 0)  Старший (Байт 1)
```
