Формат спецификатора по стандарту: `%[флаги][ширина][.точность][длина]спецификатор`. Парсить его удобнее всего в одну структуру, а форматирование делать отдельным этапом.

## Общая схема

```
s21_sprintf(str, format, ...)
 ├─ va_start
 ├─ цикл по format:
 │    ├─ обычный символ → в буфер
 │    └─ '%' → ParseSpec → FormatArg → запись в буфер
 ├─ '\0' в конец
 └─ va_end, return количество записанных символов
```

Три слоя, каждый не знает про соседей:

1. **Парсер**: из текста формата заполняет `FormatSpec`.
2. **Форматтеры**: по `FormatSpec` и аргументу собирают «тело» значения (цифры, строка).
3. **Вывод**: добавляет знак, префикс, нули и пробелы по ширине, пишет в буфер.

### Жизненный цикл

Формат обрабатывается слева направо, и в каждый момент нас интересует только текущий `%`. Схема такая:

```
"Age: %-5d| name: %s\n"
 ^^^^^^  ^^^^^^^^^^^
 обычный   %-5d  → заполнили spec → вывели → забыли
 текст             обычный текст
                   %s   → заполнили spec заново → вывели → забыли
```

`FormatSpec` описывает **один** спецификатор `%...`, тот, который обрабатывается прямо сейчас. Массив не нужен.

На каждом `%`:

1. `spec` создаётся (или обнуляется);
2. `ParseSpec` заполняет его;
3. `FormatArg` использует его, чтобы вывести значение;
4. `spec` больше не нужен: на следующем `%` он заполняется заново.

Предыдущие спецификаторы после вывода не нужны, ни один следующий от них не зависит. Поэтому хранить их нет смысла.


```c
static void ProcessFormat(Output *out, const char *fmt, va_list *args) {
  while (*fmt != '\0') {
    if (*fmt != '%') {
      PutChar(out, *fmt);
      ++fmt;
    } else {
      ++fmt;                                  // пропустили '%'
      FormatSpec spec = ParseSpec(&fmt, args);  // заполнили для ЭТОГО спецификатора
      FormatArg(out, &spec, args);              // вывели
    }                                           // spec исчезает вместе с блоком
  }
}
```

`spec` объявлен внутри ветки, поэтому на каждом проходе цикла получает «чистое» состояние. Важно, чтобы `ParseSpec` в начале инициализировал все поля: флаги нулями, `width` и `precision` значением `-1`. Иначе в структуре останется мусор или значения прошлого спецификатора.


```c
static FormatSpec InitSpec(void) {
  FormatSpec spec = {0};
  spec.width = -1;
  spec.precision = -1;
  return spec;
}
```

## Структуры

Глобальных переменных нет, поэтому всё состояние передаётся через структуры и указатели.

```c
typedef enum { kLengthNone, kLengthShort, kLengthLong, kLengthLongDouble } Length;

typedef struct {
  int minus, plus, space, hash, zero;  // флаги
  int width;                           // -1, если не задана
  int precision;                       // -1, если не задана
  Length length;
  char specifier;
} FormatSpec;

typedef struct {
  char *begin;   // начало выходной строки
  char *cursor;  // куда писать дальше
} Output;
```

`Output` заменяет «глобальный указатель». Количество записанных символов считается как `cursor - begin`. Для `%n` это тоже пригодится.

## Парсер: по функции на каждую часть

Каждая функция получает `const char **fmt` (двигает указатель) и, если нужно, `va_list *args`. Именно указатель на `va_list`: после передачи по значению состояние списка в вызывающей функции считается неопределённым.

```c
static FormatSpec ParseSpec(const char **fmt, va_list *args);
static void ParseFlags(const char **fmt, FormatSpec *spec);
static void ParseWidth(const char **fmt, va_list *args, FormatSpec *spec);
static void ParsePrecision(const char **fmt, va_list *args, FormatSpec *spec);
static void ParseLength(const char **fmt, FormatSpec *spec);
```

`ParseSpec` вызывает их строго по порядку: флаги, ширина, точность, длина, затем читает символ спецификатора. Это и есть «последовательность» из структурного программирования.

Что учесть в каждой части:

- **Флаги**: цикл `while (strchr-like проверка)` по символам `-+ #0`. Флаги можно писать в любом порядке и повторять.
- **Ширина**: либо число, либо `*` (бонус), тогда берём `va_arg(*args, int)`. Если число отрицательное, это флаг `-` плюс модуль ширины.
- **Точность**: после `.`. Если за точкой нет цифр, точность равна 0 (`%.d`, `%.s`). Для `.*` отрицательное значение означает «точность не задана».
- **Длина**: `h`, `l`, `L`.

Числа из формата читаются своей функцией (`ParseNumber`) без `atoi`, но `atoi` из stdlib разрешён, если проект не запрещает её отдельно. Проверь условие.

## Диспетчеризация

Нужна одна функция, которая по `spec.specifier` выбирает форматтер. Чтобы не плодить вложенность (лимит 4), можно использовать `switch` с вызовами функций или таблицу:

```c
static void FormatArg(Output *out, const FormatSpec *spec, va_list *args) {
  switch (spec->specifier) {
    case 'c': FormatChar(out, spec, args); break;
    case 's': FormatString(out, spec, args); break;
    case 'd': case 'i': FormatSigned(out, spec, args); break;
    case 'u': case 'o': case 'x': case 'X': FormatUnsigned(out, spec, args); break;
    case 'f': case 'e': case 'E': case 'g': case 'G': FormatFloat(out, spec, args); break;
    case 'p': FormatPointer(out, spec, args); break;
    case '%': PutChar(out, '%'); break;
  }
}
```

Если один выход из функции, `break` в `switch` допустим, так как он не выход из функции и не выход из цикла. Но всё же проверь по своему стандарту про «не более одного выхода из цикла»: `switch` не цикл, так что здесь всё в порядке.

## Форматтеры: общий приём «тело + оформление»

Для всех числовых типов схема одинакова:

1. Достать аргумент с учётом длины.
2. Превратить значение в строку цифр во временный буфер (без знака и без дополнения).
3. Передать в общую функцию `WriteField`, которая расставляет знак, префикс, нули и пробелы.

```c
static void FormatSigned(Output *out, const FormatSpec *spec, va_list *args) {
  long long value = GetSignedArg(spec, args);
  char digits[kBufferSize];
  int is_negative = value < 0;
  unsigned long long magnitude = is_negative ? 0ULL - (unsigned long long)value : (unsigned long long)value;
  int length = UnsignedToString(magnitude, 10, 0, digits);
  WriteNumber(out, spec, digits, length, GetSignChar(spec, is_negative));
}
```

Важные места:

- **Аргументы с `h`**: `short` в `va_arg` не передаётся, тип повышается до `int`. Поэтому читаем `va_arg(*args, int)` и приводим: `(short)value`. Для `l` читаем `long`. Для `u`/`x`/`o` то же самое с `unsigned`.
- **`0ULL - value`** для модуля: так не ломается `LLONG_MIN`.
- **Универсальный `UnsignedToString(value, base, uppercase, buf)`**: один код для `d`, `u`, `o`, `x`, `X`. Цифры генерируются с конца, потом разворачиваются. Это ответ на «исключить дублирование».
- **Знак**: `-` для отрицательных; иначе `+` при флаге `+`; иначе пробел при флаге пробел. Флаг `+` сильнее пробела.
- **Точность у целых** задаёт минимальное число цифр (добиваем нулями слева). При точности `0` и значении `0` цифр нет вообще.
- **Флаг `0`** игнорируется, если есть флаг `-` или у целого задана точность.


### Какой форматтер обрабатывает какой спецификатор

|Спецификатор|Кто обрабатывает|Заметка|
|---|---|---|
|`c`|`FormatChar`||
|`s`|`FormatString`||
|`d`, `i`|`FormatSigned`|при выводе `i` и `d` ничем не отличаются (разница только в `sscanf`)|
|`u`, `o`, `x`, `X`|`FormatUnsigned`|основание и регистр выбираются по спецификатору|
|`f`, `e`, `E`, `g`, `G`|`FormatFloat`|регистр (`E`/`G`) и вариант (`f`/`e`/`g`) выбираются внутри|
|`p`|`FormatPointer`|у glibc для `NULL` печатается `(nil)`, а не `0x0`|
|`%`|диспетчер `FormatArg`|форматтер не нужен: просто записать `%`|
|`n`|диспетчер `FormatArg`|ничего не печатает: записывает число уже выведенных символов по `int *` (с `h` это `short *`, с `l` это `long *`)|

`FormatArg` в таком виде остаётся «чистым» диспетчером, но `%` и `n` придётся обработать прямо в нём (или вынести в `FormatPercent` и `FormatCount`).

### Что к чему применяется

|Спецификатор|`-`|`+`|пробел|`#`|`0`|ширина|точность|длина|
|---|---|---|---|---|---|---|---|---|
|`c`|✓|–|–|–|–|✓|–|`l` (опц.)|
|`s`|✓|–|–|–|–|✓|✓ (макс. число символов)|`l` (опц.)|
|`d`, `i`|✓|✓|✓|–|✓¹|✓|✓ (мин. число цифр)|`h`, `l`|
|`u`|✓|–|–|–|✓¹|✓|✓ (мин. число цифр)|`h`, `l`|
|`o`|✓|–|–|✓ (префикс `0`)|✓¹|✓|✓ (мин. число цифр)|`h`, `l`|
|`x`, `X`|✓|–|–|✓ (префикс `0x`/`0X`, только для ненулевых)|✓¹|✓|✓ (мин. число цифр)|`h`, `l`|
|`f`, `e`, `E`|✓|✓|✓|✓ (всегда ставить точку)|✓²|✓|✓ (цифр после точки, по умолчанию 6)|`L`|
|`g`, `G`|✓|✓|✓|✓ (точка и **не** убирать нули в конце)|✓²|✓|✓ (значащих цифр, 0 считается как 1, по умолчанию 6)|`L`|
|`p`|✓|glibc: ✓|glibc: ✓|–|–|✓|–|–|
|`%`|–|–|–|–|–|–|–|–|
|`n`|–|–|–|–|–|–|–|`h`, `l`|

¹ `0` игнорируется, если есть `-` или если задана точность.  
² `0` игнорируется, если есть `-`. Для `inf`/`nan` он тоже игнорируется: выравнивание только пробелами.

Дополнительно:

- **`+` и пробел:** если указаны оба, побеждает `+`.
- **`l` перед `f/e/g`:** допустим и ни на что не влияет.
- **Точность 0 и значение 0:** для целых это пустой вывод (кроме `%#o`, где остаётся `0`).
- **Неопределённое поведение:** в клетках с `–` поведение по стандарту не определено. Тестируйте только то, что стандарт определяет, или сверяйтесь с эталонным `sprintf`.

### Как разделить работу между функциями

```
sprintf → FormatArg (диспетчер)
            ├─ c        → FormatChar     ──┐
            ├─ s        → FormatString   ──┤ только ширина и `-` (сами)
            ├─ d i      → FormatSigned   ─┐
            ├─ u o x X  → FormatUnsigned ─┼→ UnsignedToString → WriteNumber
            ├─ f e E g G→ FormatFloat    ─┤
            ├─ p        → FormatPointer  ─┘
            ├─ %        → записать '%'
            └─ n        → записать out->count по указателю
```

Ключевая идея: `WriteNumber` общий для всех чисел и отвечает за **знак, префикс, нули, ширину и `-`**. Он принимает:

- знак (`'-'`, `'+'`, `' '` или ничего);
- префикс (`0x` и т. п.);
- строку цифр;
- `min_digits` (минимальное число цифр);
- `spec`.

Порядок вывода внутри:

1. пробелы слева (если нет `-` и нет нулевого заполнения);
2. знак;
3. префикс;
4. нули (до `min_digits`, либо до ширины при флаге `0`);
5. цифры;
6. пробелы справа (если есть `-`).

Что делает каждый форматтер с точностью:

- **`FormatSigned` и `FormatUnsigned`:** передают в `WriteNumber` `min_digits = precision`. Они же ловят случай «точность 0 и значение 0», когда цифры пустые.
- **`FormatFloat`:** использует точность сам, при округлении. В `WriteNumber` он передаёт `min_digits = 0`.
- **`FormatPointer`:** формально повторяет логику `x` с префиксом `0x`.

Если `FormatFloat` станет большим, его удобно разделить на `FormatFixed` (`f`), `FormatExp` (`e`/`E`) и `FormatShortest` (`g`/`G`). `g` выбирает стиль `e`, если экспонента < -4 или ≥ P (P равно точности), иначе стиль `f`. Если нет `#`, концевые нули убираются.

## WriteNumber: ядро вывода

Порядок вывода слева направо: `[пробелы] [знак/префикс] [нули] [цифры] [пробелы]`.

```c
static void WriteNumber(Output *out, const FormatSpec *spec,
                        const char *digits, int digit_count, char sign);
```

Внутри считаем:

- `zeros_for_precision = max(0, precision - digit_count)`;
- длину содержимого = знак + префикс + нули + цифры;
- `padding = max(0, width - длина)`;
- если флаг `-`, то пробелы справа; если флаг `0` (и он не отменён), то нули идут между знаком и цифрами; иначе пробелы слева.

Для `%s` и `%c` та же идея, но проще: у `%s` точность обрезает строку, затем добавляется выравнивание по ширине. Для `NULL` стандартная библиотека печатает `(null)` на glibc, поведение зависит от платформы, поэтому смотри, какой реализации сравнивают тесты.

## Вещественные числа: самое объёмное

Для `%f` по умолчанию точность равна 6. Типичный путь:

1. `va_arg(*args, double)` (или `long double` при `L`). Тип `float` в `va_arg` не передаётся, он повышается до `double`.
2. Обработать знак (включая отрицательный ноль) и особые значения `inf`/`nan`.
3. Целая часть и дробная: домножить дробную на `10^precision`, округлить, обработать перенос в целую часть (`9.9996` с точностью 3 даёт `10.000`).
4. Склеить `целая . дробная` в буфер и передать в `WriteNumber`. Точка нужна при точности ноль только с флагом `#`.

Для `e`/`E` сначала приводим число к виду `m × 10^exp`, `g`/`G` выбирают между `f` и `e` по значению порядка и точности и убирают лишние нули (без `#`). Это отдельная порция работы, лучше сначала доделать `f`, а `e` и `g` сделать на её основе.

## Что ещё не забыть

- **Возвращаемое значение**: число символов без `\0`.
- **`%%`** просто выводит `%`.
- **`%p`**: `0x` + hex. Для NULL платформы расходятся (`(nil)` на glibc, `0x0` на macOS).
- **`%n`**: записывает по указателю количество выведенных символов (в бонусной части).
- **Неизвестный спецификатор**: реальный `sprintf` ведёт себя неопределённо, достаточно не падать.
- **Размер временного буфера**: для `%f` с большими числами нужно место под ~310 цифр для `double`.

## Порядок разработки (top-down, как у тебя в стандарте)

1. `s21_sprintf` с циклом по формату и заглушками `ParseSpec` / `FormatArg`. Сначала только обычные символы и `%%`.
2. `%c` и `%s` без модификаторов, потом `WriteField` для ширины и `-`.
3. Парсер целиком (флаги, ширина, точность, длина), пока форматтеры его используют частично.
4. `%d` / `%u` через общий `UnsignedToString`, затем точность и флаги `+`, пробел.
5. `%f`.
6. Бонус: `o`, `x`, `X`, `#`, `0`, `*`, `L`, `e`, `g`, `p`, `n`.

После каждого шага сравнивай результат с настоящим `sprintf` в юнит-тестах (Check). Удобно писать тест-функцию, которая вызывает оба варианта с одним форматом и сравнивает и строку, и возвращаемое число.


## Функции 

### Верхний уровень

**`s21_sprintf(char *str, const char *format, ...)`**  
Публичная функция, единственная в этом блоке без `static`. Делает `va_start`, создаёт `Output` (`begin = cursor = str`), вызывает `ProcessFormat`, ставит `'\0'` в конец, делает `va_end`. Возвращает `cursor - begin`, то есть число записанных символов без `'\0'`.

**`ProcessFormat(Output *out, const char *fmt, va_list *args)`**  
Главный цикл по строке формата. Обычные символы копирует в буфер. На `%` вызывает `ParseSpec`, а потом `FormatArg`. Ничего не возвращает, результат накапливается в `out`.

### Парсер (заполняет `FormatSpec`, в буфер ничего не пишет)

**`InitSpec()`**  
Возвращает «чистую» структуру: все флаги 0, `width = -1`, `precision = -1`, длина `kLengthNone`.

**`ParseSpec(const char **fmt, va_list *args)`**  
Разбирает один спецификатор целиком. Вызывает по порядку `InitSpec`, `ParseFlags`, `ParseWidth`, `ParsePrecision`, `ParseLength`, затем читает символ спецификатора (`d`, `s`, `f` и так далее) в `spec.specifier` и сдвигает `*fmt` за него. Возвращает заполненную `FormatSpec`.

**`ParseFlags(const char **fmt, FormatSpec *spec)`**  
Пока текущий символ один из `-+ #0`, ставит соответствующее поле в 1 и двигает указатель. Конфликты флагов здесь не разрешает.

**`IsFlag(char c)`**  
Вспомогательная: возвращает 1, если `c` один из `-`, `+`, пробел, `#`, `0`. Нужна, чтобы условие цикла в `ParseFlags` читалось легко.

**`ParseWidth(const char **fmt, va_list *args, FormatSpec *spec)`**  
Если дальше цифры, читает число через `ParseNumber` в `spec->width`. Если `*`, берёт `va_arg(*args, int)`; отрицательное значение превращает в флаг `minus` и модуль ширины. Если ничего нет, оставляет `-1`.

**`ParsePrecision(const char **fmt, va_list *args, FormatSpec *spec)`**  
Работает, только если встретилась `.`. После неё: число, либо `*` (из `va_arg`, отрицательное значит «не задана»), либо ничего, тогда точность 0.

**`ParseNumber(const char **fmt)`**  
Читает подряд идущие цифры, двигает указатель, возвращает число. Используется для ширины и точности.

**`ParseLength(const char **fmt, FormatSpec *spec)`**  
Смотрит на `h`, `l`, `L`; записывает в `spec->length` соответствующий `Length` и двигает указатель. Если модификатора нет, остаётся `kLengthNone`.

### Диспетчер и форматтеры

**`FormatArg(Output *out, const FormatSpec *spec, va_list *args)`**  
Диспетчер: по `spec->specifier` выбирает нужный форматтер и вызывает его. Сама ничего не форматирует.

**`FormatChar(...)`**  
Берёт `va_arg(*args, int)`, превращает в символ и выводит с учётом ширины и флага `-`. Точность не использует.

**`FormatString(...)`**  
Берёт `const char *`. При точности обрезает строку до этого числа символов. Затем выводит с выравниванием по ширине. Для `NULL` подставляет текст, который печатает эталонная реализация (`(null)` на glibc).

**`FormatSigned(...)`** (`d`, `i`)  
Достаёт знаковое значение с учётом `h`/`l` через `GetSignedArg`, отделяет знак от модуля, переводит модуль в цифры через `UnsignedToString`, затем передаёт в `WriteNumber`.

**`FormatUnsigned(...)`** (`u`, `o`, `x`, `X`)  
То же без знака. Основание (10, 8, 16) и регистр цифр выбирает по спецификатору. Для `#` готовит префикс (`0` или `0x`/`0X`).

**`FormatFloat(...)`** (`f`, затем `e`, `g`)  
Читает `double` или `long double` (для `L`), обрабатывает знак и `inf`/`nan`, округляет до нужной точности (по умолчанию 6), собирает строку `целая.дробная` и передаёт в `WriteNumber`.

**`FormatPointer(...)`** (`p`)  
Читает `void *`, превращает в число, выводит как `0x` + hex через `UnsignedToString`.

### Вспомогательные

**`GetSignedArg(const FormatSpec *spec, va_list *args)`**  
Читает целый аргумент нужного типа (`int` или `long`) и приводит к `short`, если указано `h`. Возвращает `long long` для единообразия.

**`GetSignChar(const FormatSpec *spec, int is_negative)`**  
Решает, какой знак ставить перед числом: `-` для отрицательных, иначе `+` при флаге `plus`, иначе пробел при флаге `space`, иначе ничего (`'\0'`). Здесь же разрешается конфликт `+` и пробела.

**`UnsignedToString(unsigned long long value, int base, int uppercase, char *buf)`**  
Записывает цифры числа в буфер (в нужном основании, нужным регистром), возвращает их количество. Общая функция для `d`, `u`, `o`, `x`, `X`, `p`.

**`WriteNumber(Output *out, const FormatSpec *spec, const char *digits, int digit_count, char sign)`**  
Ядро вывода чисел. Считает нули по точности и пробелы по ширине, учитывает флаги `-` и `0`, затем пишет по порядку: пробелы слева, знак/префикс, нули, цифры, пробелы справа.

**`PutChar(Output *out, char c)`**  
Записывает один символ в `*out->cursor` и сдвигает `cursor`. Все остальные функции вывода строятся на ней (и, при желании, на `PutRepeated(out, c, count)` для нулей и пробелов).

### Кто кого вызывает

```
s21_sprintf
 └─ ProcessFormat
     ├─ PutChar                      (обычный текст)
     ├─ ParseSpec
     │   ├─ InitSpec
     │   ├─ ParseFlags → IsFlag
     │   ├─ ParseWidth → ParseNumber
     │   ├─ ParsePrecision → ParseNumber
     │   └─ ParseLength
     └─ FormatArg
         ├─ FormatChar / FormatString
         ├─ FormatSigned / FormatUnsigned / FormatFloat / FormatPointer
         │     └─ GetSignedArg, GetSignChar, UnsignedToString
         └─ все числовые → WriteNumber → PutChar
```
