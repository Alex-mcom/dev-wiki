`systemd` (**system daemon**) — это система инициализации и менеджер служб в современных дистрибутивах Linux (Ubuntu, Debian, Fedora, Arch и др.). Это первый процесс, который запускает ядро после загрузки. Он имеет **PID 1** и отвечает за всё, что происходит дальше: запуск служб, монтирование дисков, настройку сети, управление сессиями пользователей.

>Суффикс `d` в Unix означает daemon (фоновая служба): `sshd`, `crond`


## Юниты

Основная сущность systemd — **юнит** (unit): описание того, чем он управляет. Хранится в файлах `.service`, `.timer` и т. д. в `/lib/systemd/system/` и `/etc/systemd/system/`.

|Тип юнита|Что описывает|
|---|---|
|`.service`|Служба (демон), например `ssh.service`|
|`.socket`|Сокет, при обращении к которому запускается служба|
|`.target`|Группа юнитов, аналог «уровня запуска» (`multi-user.target`)|
|`.timer`|Запуск по расписанию, аналог cron|
|`.mount`|Точка монтирования файловой системы|
|`.device`|Устройство, обнаруженное udev|
|`.path`|Слежение за файлом или каталогом|

## Основные компоненты

|Компонент|Команда|Назначение|
|---|---|---|
|Менеджер служб|`systemctl`|Запуск, остановка, автозагрузка, статус служб|
|Журналирование|`journald`, `journalctl`|Сбор и просмотр системных логов|
|Сеть|`systemd-networkd`, `networkctl`|Настройка сетевых интерфейсов (его использует netplan)|
|DNS|`systemd-resolved`, `resolvectl`|Разрешение имён и DNS-кэш|
|Время|`systemd-timesyncd`, `timedatectl`|Синхронизация времени и часовой пояс|
|Имя хоста|`systemd-hostnamed`, `hostnamectl`|Управление hostname|
|Сессии|`systemd-logind`, `loginctl`|Вход пользователей, сессии, питание|
|Устройства|`systemd-udevd`, `udevadm`|Обнаружение и настройка устройств|
|Анализ загрузки|`systemd-analyze`|Время загрузки и «узкие места»|

Есть и менее заметные части: `systemd-tmpfiles` (временные файлы), `systemd-oomd` (защита от нехватки памяти), `systemd-machined` (контейнеры и виртуальные машины).


## `systemctl`

`systemctl` (**system control**) входит в состав `systemd`, но это не демон, а **клиентская утилита командной строки**. Сам `systemd` (PID 1) работает в фоне. `systemctl` отправляет ему запросы («запусти службу», «покажи статус») через **D-Bus** и выводит ответ. Вся реальная работа выполняется самим systemd.

```
Ты → systemctl → D-Bus → systemd (PID 1) → запуск/остановка процессов
```

```bash
systemctl [ОПЦИИ] КОМАНДА [ЮНИТ...]
```

>Если у юнита не указан суффикс, подразумевается `.service`: `systemctl status ssh` — это `ssh.service`.


```bash
systemctl status ssh          # состояние службы
sudo systemctl start ssh      # запустить
sudo systemctl stop ssh       # остановить
sudo systemctl restart ssh    # перезапустить
sudo systemctl enable ssh     # добавить в автозагрузку
sudo systemctl disable ssh    # убрать из автозагрузки
systemctl list-units --type=service   # список служб
journalctl -u ssh             # логи конкретной службы
```


**Управление службами**

|Команда|Действие|
|---|---|
|`start` / `stop`|Запустить / остановить сейчас|
|`restart`|Остановить и запустить заново|
|`reload`|Перечитать конфиг без остановки (если служба поддерживает)|
|`enable` / `disable`|Добавить / убрать из автозагрузки|
|`enable --now`|Включить автозагрузку и сразу запустить|
|`mask` / `unmask`|Полностью запретить / разрешить запуск службы|
|`kill`|Отправить сигнал процессам юнита|

**Просмотр состояния**

|Команда|Действие|
|---|---|
|`status`|Подробное состояние и последние строки лога|
|`is-active`|Работает ли служба (удобно для скриптов)|
|`is-enabled`|Включена ли автозагрузка|
|`is-failed`|Завершилась ли служба с ошибкой|
|`list-units`|Список загруженных юнитов|
|`list-unit-files`|Все установленные юниты и их состояние автозагрузки|
|`list-timers`|Активные таймеры|
|`list-dependencies`|Дерево зависимостей юнита|
|`cat`|Показать содержимое unit-файла|
|`show`|Все свойства юнита в формате `ключ=значение`|

**Конфигурация и система**

|Команда|Действие|
|---|---|
|`edit`|Создать или изменить override-файл юнита|
|`daemon-reload`|Перечитать unit-файлы после правок|
|`get-default` / `set-default`|Цель загрузки (`multi-user.target`, `graphical.target`)|
|`isolate`|Перейти в другую цель|
|`reboot`, `poweroff`, `suspend`|Управление питанием|

**Дополнительные режимы**

- `--user` — управление пользовательскими службами, без root.
- `-H user@host` — управление systemd на удалённой машине по SSH.
- `-M имя` — управление контейнером.

### Пример вывода status

```
● ssh.service - OpenBSD Secure Shell server
     Loaded: loaded (/usr/lib/systemd/system/ssh.service; enabled; preset: enabled)
     Active: active (running) since Mon 2026-11-23 10:15:02 MSK; 2h ago
   Main PID: 842 (sshd)
      Tasks: 1 (limit: 4547)
     Memory: 5.2M
     CGroup: /system.slice/ssh.service
             └─842 "sshd: /usr/sbin/sshd -D [listener]"
```

- **Loaded** — файл юнита найден, `enabled` означает автозагрузку.
- **Active** — текущее состояние: `active (running)`, `inactive (dead)`, `failed`.
- **Main PID** — основной процесс службы.
- **CGroup** — группа процессов, принадлежащих службе.
- Под блоком выводятся последние строки журнала.


## `hostnamectl`

Имя хоста (hostname) — название компьютера в сети. Задаётся командой `hostnamectl`, изменения сохраняются в `/etc/hostname`.

```bash
sudo hostnamectl set-hostname user-1   # задать имя
hostnamectl                            # проверить
```

>Изменения вступают в силу сразу. Чтобы приглашение в терминале обновилось, нужно перелогиниться.

Имя хоста не привязано к пользователю, потому что это свойство машины, а не учётной записи. Пользователь — это один из аккаунтов внутри системы, а hostname — название самой системы. Поэтому имя хранится в `/etc/hostname`, и оно одно на всех. Поэтому в приглашении `user@user-1:~$` две части берутся из разных мест: до `@` — текущий пользователь сессии, после — имя машины.

Если зайти на машину под разными пользователями, имя хоста будет одним и тем же:

```bash
ssh alice@192.168.1.10   # приглашение: alice@user-1
ssh bob@192.168.1.10     # приглашение: bob@user-1
```

Подключение идёт к **машине**, а пользователь только выбирает, под какой учёткой в ней работать. Аналогия: у дома один адрес, а жильцов в нём может быть много.

Не стоит и считать hostname «адресом» в сети. Для сети важен IP, а hostname — удобная метка, которую другие компьютеры могут преобразовывать в IP через DNS, `/etc/hosts` или mDNS. Он не обязан быть уникальным в мире, поэтому две машины с одинаковым именем в одной сети вызовут путаницу.


## `timedatectl`

```bash
timedatectl list-timezones | grep Moscow   # найти нужный пояс
sudo timedatectl set-timezone Europe/Moscow
timedatectl                                # проверить
```

В выводе строка `Time zone` должна показывать выбранный пояс. Формат названия: `Регион/Город`.
