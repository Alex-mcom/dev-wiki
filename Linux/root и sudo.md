## Root

Root — суперпользователь с UID 0. Ему разрешено всё: читать и менять любые
файлы, управлять процессами, удалять систему целиком. Ядро не проверяет права
root, поэтому любая ошибка или вредоносная команда выполнится без защиты.

Работа под root опасна по нескольким причинам:

- опечатка в `rm -rf` ничем не ограничена
- любая запущенная программа получает полные права
- нет разделения, кто что сделал, в логах просто «root»


### Root в Ubuntu

В Ubuntu учётная запись root существует, но заблокирована: у неё нет пароля,
войти под ней напрямую нельзя. Поэтому установщик просит создать обычного
пользователя. Его автоматически добавляют в группу `sudo`, и он получает
административные права через sudo.

Проверить состояние root: `sudo passwd -S root` (статус `L` означает
«заблокирован»).

В Debian установщик, наоборот, предлагает задать пароль root.


## Sudo

`sudo` позволяет выполнить команду от имени другого пользователя,
по умолчанию root. Это не «волшебное слово», а механизм точечного
делегирования прав.

Что даёт sudo по сравнению со входом под root:

- права повышаются только на время одной команды
- запрашивается пароль текущего пользователя
- каждое использование пишется в `/var/log/auth.log`, видно, кто и что запускал
- права можно ограничить: разрешить только определённые команды
  определённым пользователям

Настройка находится в `/etc/sudoers` и `/etc/sudoers.d/`. Редактировать
только через `sudo visudo`, он проверяет синтаксис: ошибка в файле может
лишить доступа к sudo.

Выдать право sudo пользователю:

    sudo usermod -aG sudo patrik

Полезные варианты:

    sudo -i       # shell root (с загрузкой окружения root)
    sudo -u user cmd   # выполнить от имени другого пользователя


## VPS и вход под root

Провайдер создаёт сервер автоматически из готового образа, интерактивного
установщика нет. Чтобы дать владельцу доступ сразу, провайдер включает root
и присылает пароль или записывает ваш SSH-ключ. Исключения есть: на некоторых
облаках (например, образы Ubuntu в AWS) вход идёт под обычным пользователем
`ubuntu` с sudo.

Root с известным именем и доступом по SSH постоянно атакуют перебором паролей:
имя угадывать не нужно, остаётся подобрать пароль. Поэтому после получения
сервера нужно сразу настроить безопасный вход.


## Первичная настройка сервера

1. Войти под root и создать обычного пользователя:

       adduser patrik
       usermod -aG sudo patrik

2. Скопировать SSH-ключ новому пользователю (`ssh-copy-id patrik@server`)
   и проверить вход под ним.
3. Отключить вход root по SSH в `/etc/ssh/sshd_config`:

       PermitRootLogin no

4. По желанию отключить вход по паролю (`PasswordAuthentication no`)
   и сменить порт SSH.
5. Перезапустить службу: `sudo systemctl restart ssh`.

Дальше администрировать сервер нужно через обычного пользователя и sudo.
Не закрывайте текущую сессию, пока не убедились, что вход под новым
пользователем работает.
