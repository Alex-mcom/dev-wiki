### Внешний IP-адрес (ip)

Это **публичный адрес, под которым твоя сеть видна в интернете**. Он принадлежит внешней стороне маршрутизатора (шлюза), который выпускает тебя в интернет. Его выдаёт провайдер, и он не совпадает с адресом внутри виртуалки.

Как посмотреть: запросить его у внешнего сервиса, потому что внутри системы этот адрес не виден.


```bash
curl 2ip.io
```

Так как виртуалка работает через NAT, внешний адрес у неё общий с хост-машиной (и со всей твоей домашней сетью).

### Внутренний IP-адрес шлюза (gw)

Это **адрес маршрутизатора внутри твоей локальной сети**, на который машина отправляет весь трафик, предназначенный не для её подсети. Его называют шлюзом по умолчанию (default gateway). Именно его нужно указывать как `gw` в статической настройке.

```bash
ip r
```

Пример вывода:

```
default via 192.168.64.1 dev enp0s1 proto dhcp src 192.168.64.2 metric 100
192.168.64.0/24 dev enp0s1 proto kernel scope link src 192.168.64.2 metric 100
192.168.64.1 dev enp0s1 proto dhcp scope link src 192.168.64.2 metric 100
```

| Строка                       | Значение                                                               |
| ---------------------------- | ---------------------------------------------------------------------- |
| `default via 192.168.64.1`   | Шлюз по умолчанию. Это и есть **gw = `192.168.64.1`**                  |
| `192.168.64.0/24 dev enp0s1` | Локальная подсеть: адреса `192.168.64.x` достижимы напрямую, без шлюза |
| `192.168.64.1 dev enp0s1`    | Отдельный маршрут до самого шлюза, добавленный DHCP                    |
| `src 192.168.64.2`           | Адрес самой виртуалки                                                  |
| `proto dhcp`                 | Параметры получены от DHCP-сервера                                     |
| `enp0s1`                     | Имя интерфейса (в UTM оно `enp0s1`, а не `enp0s3`, как в VirtualBox)   |


### Что такое шлюз в Shared Network

В режиме Shared Network macOS создаёт виртуальную сеть и сам выступает в ней маршрутизатором, DHCP-сервером и NAT. Поэтому `192.168.64.1` это интерфейс твоего Mac в этой виртуальной подсети. Трафик идёт так:

```
VM (192.168.64.2) → Mac (192.168.64.1) → домашний роутер → интернет
```

>От режима «мост» отличие в том, что виртуалка не видит твою домашнюю сеть напрямую и сидит в подсети `192.168.64.0/24`.


## Статическая настройка сети

В Ubuntu 24.04 сеть настраивается через **netplan**. Конфиги лежат в `/etc/netplan/*.yaml`.

```bash
ls /etc/netplan/
sudo nano /etc/netplan/50-cloud-init.yaml
```

Пример статической конфигурации для UTM (NAT):

```yaml
network:
  version: 2
  ethernets:
    enp0s1:
      dhcp4: false
      addresses:
        - 192.168.64.10/24
      routes:
        - to: default
          via: 192.168.64.1
      nameservers:
        addresses:
          - 1.1.1.1
          - 8.8.8.8
```

- отступы в YAML только пробелами, табуляция недопустима;
- имя интерфейса должно совпадать с выводом `ip a`;
- параметр `gateway4` устарел, вместо него используется `routes` с `to: default`;
- файл должен иметь права `600`: `sudo chmod 600 /etc/netplan/50-cloud-init.yaml`.


**Применение настроек:**

```bash
sudo netplan try      # применить с автооткатом через 120 сек, если связь пропала
sudo netplan apply    # применить окончательно
```

Значения `ip`, `gw`, `dns` задаются вручную и больше не зависят от DHCP.


**Проверка после перезагрузки**

```bash
sudo reboot
```

```bash
ip a                # статический IP
ip r                # шлюз по умолчанию
resolvectl status   # DNS-серверы
```

Если все три параметра совпадают с указанными в netplan, статическая конфигурация сохранилась.


**Проверка связи**

```bash
ping -c 4 1.1.1.1
ping -c 4 ya.ru
```

Успешный результат содержит строку `0% packet loss`.

- Пинг `1.1.1.1` проверяет доступ в интернет по IP.
- Пинг `ya.ru` дополнительно проверяет работу DNS (преобразование имени в адрес).
- Если `1.1.1.1` отвечает, а `ya.ru` нет — проблема в DNS-настройках.
- Если не отвечает ничего — проверить шлюз и режим сетевого адаптера в VirtualBox.
