**Покрытие кода (code coverage)** показывает, какие части программы выполнялись во время тестов. Метрики:

- **Line coverage**: какие строки выполнились.
- **Function coverage**: какие функции были вызваны.
- **Branch coverage**: какие ветки условий (`if`, `?:`, `&&`, `||`, `switch`, циклы) сработали в обе стороны.

Три инструмента работают цепочкой:

|Инструмент|Что делает|
|---|---|
|**gcov**|Утилита из GCC. Читает данные профилирования и выдаёт текстовый отчёт по строкам (`.gcov`).|
|**lcov**|Обёртка над gcov. Собирает данные по всему проекту в один файл-трейс (`.info`), умеет фильтровать, складывать и сбрасывать.|
|**genhtml**|Входит в пакет lcov. Превращает `.info` в HTML-отчёт с подсветкой кода.|

```
исходники (.c) ──gcc --coverage  ──► .o + .gcno
запуск тестов                    ──► .gcda
.gcno + .gcda ──gcov             ──► .c.gcov (текстовый отчёт)
.gcno + .gcda ──lcov             ──► coverage.info 
genhtml                          ──► report/index.html
```


## Инструментирование при компиляции

Флаг `--coverage` при компиляции и линковке эквивалентен:

- при компиляции: `-fprofile-arcs -ftest-coverage`;
- при линковке: `-lgcov`.

Компилятор вставляет в код счётчики на **дугах графа потока управления** (arcs): сколько раз прошли по каждому переходу между базовыми блоками.

>Компилируйте с `-O0` (или вообще без `-O`) и с `-g`. При оптимизации компилятор переставляет и сливает код, и привязка к строкам становится неточной.


```c
CFLAGS = -std=c11 -Wall -Wextra -g -MMD -MP

$(CC) $(CFLAGS) --coverage -O0 -c $(SRCS)
```

|Файл|Когда создаётся|Содержимое|
|---|---|---|
|`*.gcno`|При **компиляции**|«Заметки»: структура графа, соответствие блоков строкам исходника.|
|`*.gcda`|При **запуске** программы (при нормальном завершении)|Значения счётчиков. Лежит рядом с `.o`.|
|`*.gcov`|После запуска `gcov`|Исходник с числом выполнений каждой строки.|
|`*.info`|После `lcov --capture`|Трейс-файл lcov (текстовый формат).|

Важно:
- Счётчики в `.gcda` **накапливаются** между запусками. Новый прогон прибавляется к старому.
- `.gcno` и `.gcda` должны быть от **одной и той же сборки**. После правки исходника старые `.gcda` надо удалить, иначе будут ошибки или мусор.
- Версия gcov должна совпадать с версией gcc, которым собирали.


## `gcov`

Обычно gcov не используется напрямую и отдельные флаги для неё не указываются. Чаще всего его вызывает `lcov` сразу для всех объектных файлов и упаковывает отчёт в один `report.info`

```bash
gcc --coverage -O0 -g -c foo.c -o foo.o    # создаст foo.gcno
gcc --coverage foo.o main.o -o app         # линковка с --coverage
./app                                      # создаст foo.gcda
gcov foo.c                                 # создаст foo.c.gcov
```

```
File 'foo.c'
Lines executed:85.71% of 14
Creating 'foo.c.gcov'
```

### Формат `.gcov`

```
        -:    0:Source:foo.c
        5:    3:int abs_val(int x) {
        5:    4:    if (x < 0)
        2:    5:        return -x;
        3:    6:    return x;
    #####:    7:    unreachable();
        -:    8:}
```

- число: сколько раз строка выполнилась;
- `-`: строка не содержит исполняемого кода (комментарии, объявления, `}`);
- `#####`: исполняемая строка, которая **ни разу не выполнялась**;
- `=====`: код, выполняющийся только при исключениях (в основном C++).

### Основные опции

|Опция|Смысл|
|---|---|
|`-b`, `--branch-probabilities`|Вероятности ветвлений и число вызовов.|
|`-c`, `--branch-counts`|Для веток выводить абсолютные числа, а не проценты.|
|`-a`, `--all-blocks`|Статистика по каждому базовому блоку.|
|`-f`, `--function-summary`|Сводка по функциям.|
|`-o dir`|Каталог с `.gcno`/`.gcda`.|
|`-n`, `--no-output`|Не создавать `.gcov`, только сводку.|
|`-t`, `--stdout`|Вывод в stdout вместо файла.|
|`-r`, `--relative-only`|Только файлы с относительными путями.|
|`-p`, `--preserve-paths`|Сохранять полные пути в именах `.gcov`.|
|`-j`, `--json-format`|Вывод в JSON (gcov ≥ 9).|
|`-i`, `--stdout` + `--json-format`|Промежуточный формат (в новых версиях).|


## `lcov`

Обёртка над `gcov`. Запускает `gcov` по всем объектникам проекта и собирает данные по всему проекту в один файл-трейс (`.info`), умеет фильтровать, складывать и сбрасывать.

```bash
lcov --capture --directory . --output-file coverage.info
```

Сокращённо: `lcov -c -d . -o coverage.info`.


### Основные опции

|Опция|Смысл|
|---|---|
|`-c`, `--capture`|Собрать данные из `.gcda` в tracefile.|
|`-d`, `--directory DIR`|Где искать `.gcda`/`.gcno` (рекурсивно).|
|`-o`, `--output-file FILE`|Куда писать результат.|
|`-z`, `--zerocounters`|Обнулить счётчики (удаляет `.gcda`).|
|`-i`, `--initial`|Создать «нулевой» baseline: файлы, которых тесты вообще не коснулись, тоже попадут в отчёт с 0%.|
|`-a`, `--add-tracefile FILE`|Сложить трейс-файлы (можно несколько `-a`).|
|`-r`, `--remove FILE PATTERN...`|Убрать из трейса файлы по маске.|
|`-e`, `--extract FILE PATTERN...`|Оставить только файлы по маске.|
|`-l`, `--list FILE`|Показать содержимое tracefile по файлам.|
|`--summary FILE`|Короткая сводка (строки, функции, ветки).|
|`--no-external`|Исключить файлы вне базового каталога (системные заголовки).|
|`-b`, `--base-directory DIR`|Базовый каталог для относительных путей.|
|`--gcov-tool PATH`|Какой gcov использовать (нужно на macOS с clang).|
|`--rc lcov_branch_coverage=1`|Включить branch coverage (lcov 1.x).|
|`--branch-coverage`|То же в lcov 2.x.|
|`--ignore-errors TYPE`|Игнорировать указанные ошибки (`gcov`, `source`, `unused` и т.д.).|
|`-q`, `--quiet`|Тише.|

Версии lcov 1.x и 2.x отличаются по опциям и по строгости к ошибкам, поэтому смотрите `lcov --version` и `man lcov`.

```c
lcov --gcov-tool $(GCOV) --branch-coverage -t "s21_string" -o report.info -c -d .
```


### Фильтрация

**Убираем из отчёта тесты и системные заголовки:**

```bash
lcov --remove coverage.info '/usr/*' '*/tests/*' '*test*' \
     --output-file coverage.filtered.info
```

Паттерны это glob-маски. Их нужно брать в одинарные кавычки, чтобы shell не раскрыл их заранее.


**Оставить только нужное:**

```bash
lcov --extract coverage.info '*/src/*' -o coverage.src.info
```


### Формат tracefile (`.info`)

```
TN:                      # имя теста
SF:/path/to/foo.c        # исходный файл
FN:3,abs_val             # функция: строка, имя
FNDA:5,abs_val           # сколько раз вызвана
FNF:1                    # функций всего
FNH:1                    # функций вызвано
BRDA:4,0,0,2             # ветка: строка, блок, ветка, сколько раз взята ('-' если не достигнута)
BRF:2                    # веток всего
BRH:2                    # веток взято
DA:4,5                   # строка 4 выполнена 5 раз
LF:14                    # строк всего
LH:12                    # строк выполнено
end_of_record
```


### Baseline-трюк

Если тесты вообще не затронули какой-то файл, он не попадёт в отчёт, и покрытие выглядит лучше, чем есть. Решение:

```bash
lcov -c -i -d . -o base.info        # до запуска тестов: нулевое покрытие
./run_tests
lcov -c -d . -o test.info           # после тестов
lcov -a base.info -a test.info -o coverage.info
```


## `genhtml`

Входит в пакет `lcov`. Превращает `.info` в HTML-отчёт с подсветкой кода

```bash
genhtml coverage.info --output-directory report
```

Откройте `report/index.html` в браузере.

**Что в отчёте**
- главная страница: таблица по каталогам с цветовыми порогами (низкий / средний / высокий, по умолчанию примерно 75% и 90%);
- страница файла: исходник с числом выполнений слева, красным подсвечены непокрытые строки, отдельный столбец под ветки (`+` взята, `-` не взята).


### Основные опции

|Опция|Смысл|
|---|---|
|`-o`, `--output-directory DIR`|Каталог для HTML.|
|`--branch-coverage`|Показать покрытие веток (в lcov 1.x: `--rc genhtml_branch_coverage=1`).|
|`--function-coverage`|Показать покрытие функций (в lcov 2.x включено по умолчанию).|
|`-t`, `--title TEXT`|Заголовок отчёта.|
|`--legend`|Добавить легенду с цветами.|
|`--show-details`, `-s`|Страницы с подробностями по тестам.|
|`--prefix PATH`|Убрать общий префикс путей.|
|`--no-source`|Не показывать исходники.|
|`--demangle-cpp`|Расшифровка имён C++.|
|`--sort` / `--no-sort`|Сортировка таблиц.|
|`--highlight`|Подсвечивать строки, выполненные только тестами из `--diff`-набора.|
|`--num-spaces N`|Ширина таба.|
|`--ignore-errors TYPE`|Игнорировать ошибки (например, `source`, если исходник не найден).|
