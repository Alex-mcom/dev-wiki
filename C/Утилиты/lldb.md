LLDB — отладчик из проекта LLVM. Умеет останавливать программу в нужном месте, показывать значения переменных и памяти, выполнять код по шагам и менять состояние процесса на лету. Это штатный отладчик на macOS, а в Linux ставится отдельно (пакет `lldb`).

- Отладчик работает с готовым исполняемым файлом и **отладочной информацией** в нём (формат DWARF). Без неё он видит только адреса и ассемблер, поэтому программу нужно собирать с флагом `-g`.
- Точка останова реализована подменой машинной инструкции на специальную (на x86 это `int3`). Когда процессор доходит до неё, ОС посылает отладчику сигнал, и программа замирает. Отладчик возвращает исходную инструкцию и показывает состояние.
- Управление чужим процессом идёт через средства ОС: `ptrace` в Linux, Mach API на macOS. На практике этим занимается отдельный серверный процесс (`debugserver` или `lldb-server`), а сам LLDB общается с ним по протоколу.
- Выражения (`print`, `expression`) разбирает и компилирует встроенный компилятор Clang. Поэтому в отладчике можно писать почти настоящий C: вызывать функции, приводить типы, менять переменные.
- Ядро LLDB — библиотека с публичным API. Консоль, VS Code и другие оболочки — лишь клиенты этой библиотеки.

VS Code сам отладчиком не является. Он использует расширение-адаптер:

- **CodeLLDB** (рекомендуемый вариант) — подключает LLDB напрямую, в отладочной консоли можно вводить команды LLDB.
- **C/C++ от Microsoft** с режимом `lldb` — работает через прослойку, команды LLDB нужно писать с префиксом `-exec`.

Отладочная консоль (панель Debug Console) работает только в момент, когда программа поставлена на паузу.

## Ввод команд в консоли

В CodeLLDB поведение консоли зависит от настройки `lldb.consoleMode`:

|Режим|Что значит ввод без префикса|Как переключиться на другое|
|---|---|---|
|commands|это команда LLDB (`bt`, `v`, `e a = 5`)|префикс `?` вычисляет выражение на C|
|evaluate|это выражение на C|префикс из обратного апострофа даёт команду LLDB|

Если в консоли команды работают без префикса, значит включён режим commands. В расширении C/C++ от Microsoft команды пишутся с префиксом `-exec` (например, `-exec bt`).

## Подготовка к отладке

- Сборка с отладочной информацией и без оптимизаций: `gcc -g -O0 -std=c11 main.c -o app`
- Оптимизации (`-O2`, `-O3`) убирают переменные и перемешивают строки, из-за чего отладка выглядит странно.
- В `launch.json` указывается путь к собранному файлу и аргументы запуска (`args`).

## Точки останова

|Команда|Что делает|
|---|---|
|`b main`|остановка на входе в функцию|
|`b file.c:42`|остановка на строке файла|
|`br list`|список всех точек останова|
|`br disable 1`|временно отключить точку с номером 1|
|`br enable 1`|включить обратно|
|`br delete 1`|удалить точку с номером 1|
|`br delete`|удалить все точки (спросит подтверждение)|
|`b file.c:42 -c "i == 10"`|условная точка: сработает, только если условие истинно|
|`br modify 1 -c "i > 5"`|добавить или изменить условие|
|`br modify 1 -i 3`|пропустить первые три срабатывания|
|`tbreak file.c:42`|одноразовая точка|
|`br set -r "s21_"`|точки на все функции, подходящие под регулярное выражение|

В VS Code точки удобно ставить кликом слева от номера строки, а условия задавать через контекстное меню.

## Управление выполнением

|Команда|Сокращение|Что делает|
|---|---|---|
|`continue`|`c`|продолжить до следующей точки|
|`next`|`n`|выполнить строку, не заходя в функции|
|`step`|`s`|выполнить строку, заходя в функции|
|`finish`|—|выполнять до выхода из текущей функции|
|`thread until 50`|—|выполнять до строки 50 (удобно, чтобы проскочить цикл)|
|`thread step-inst`|`si`|один шаг на уровне машинной инструкции|
|`thread return`|—|немедленно выйти из функции (можно с возвращаемым значением)|
|`process interrupt`|—|остановить работающую программу|
|`process kill`|—|прервать отлаживаемый процесс|

## Просмотр переменных

|Команда|Что делает|
|---|---|
|`frame variable` или `v`|все локальные переменные текущей функции|
|`v name`|одна переменная|
|`v -r name`|с раскрытием вложенных структур|
|`p expr`|вычислить выражение и вывести результат|
|`p *ptr`|значение по указателю|
|`p arr[2]`|элемент массива|
|`p node->next->value`|разыменование цепочки указателей|
|`p sizeof(struct data)`|размер типа|
|`p (char)65`|приведение типа|
|`p &var`|адрес переменной|

Команда `v` читает переменные напрямую из памяти и работает быстрее и надёжнее, чем `p`. Команда `p` вычисляет любое выражение на C.

### Форматы вывода

Формат пишется через слэш: `p/x var`.

|Формат|Результат|
|---|---|
|`/d`|десятичное знаковое|
|`/u`|десятичное беззнаковое|
|`/x`|шестнадцатеричное|
|`/o`|восьмеричное|
|`/t`|двоичное|
|`/c`|символ|
|`/s`|строка|
|`/f`|число с плавающей точкой|
|`/a`|адрес|

Пример: `p/t flags` покажет биты флагов, `p/x ptr` — адрес в шестнадцатеричном виде.

### Массивы и строки

- Статический массив выводится целиком: `p arr` или `v arr`.
- Динамический массив по указателю нужно показывать с указанием длины: `expression -Z 5 -- ptr` (покажет пять элементов начиная с `ptr`).
- Строка по указателю: `p str` или `p/s str`.
- Отдельный символ строки: `p str[3]` или `p/c str[3]`.
- Определить длину строки на лету: `p strlen(str)` (если функция доступна в программе).
- Чтобы увидеть, где заканчивается строка, смотри нулевой байт: `memory read -c 16 -f x str`.

## Чтение памяти

Команда `memory read` (сокращённо `x`) показывает сырую память.

|Команда|Что делает|
|---|---|
|`memory read ptr`|прочитать память по адресу|
|`memory read -c 16 ptr`|прочитать 16 элементов|
|`memory read -s1 -fx -c 32 ptr`|32 байта в шестнадцатеричном виде|
|`memory read -t int -c 5 -fd arr`|пять значений типа `int` в десятичном виде|
|`memory read -fs ptr`|интерпретировать как строку|
|`memory read -fc -c 10 ptr`|десять символов|

Флаги: `-c` — количество, `-s` — размер элемента в байтах, `-f` — формат, `-t` — тип.

Полезно, когда нужно проверить границы буфера, увидеть мусор после завершающего нуля или понять, что реально записала функция вроде `memcpy`.

## Изменение состояния

| Команда                      | Что делает                                                 |
| ---------------------------- | ---------------------------------------------------------- |
| `e x = 10`                   | присвоить значение переменной                              |
| `expr arr[0] = 'A'`          | изменить элемент массива                                   |
| `expr ptr = 0`               | занулить указатель                                         |
| `expr my_func(5)`            | вызвать функцию программы                                  |
| `expr -- (int)strlen("abc")` | вызвать библиотечную функцию с приведением типа результата |

Так можно проверить гипотезу, не пересобирая программу.

## Выражения подробнее

- `expression` сокращается до `expr` и до `e`: `e a = 4` то же самое, что `expression a = 4`.
- Внутри выражения работает почти любой C: арифметика, приведения типов, тернарный оператор, вызовы функций, циклы и условия.
- Обычную переменную в выражении объявить нельзя, но можно создать **переменную отладчика** с именем, начинающимся со знака доллара. Она живёт до конца сеанса и доступна в следующих командах.

```
e int $sum = 0
e for (int j = 0; j < 5; j++) { $sum += arr[j]; }
p $sum
```

- Результаты каждого выражения сохраняются автоматически как `$0`, `$1` и так далее. Их можно использовать повторно: `p $3 + 1`.
- Присваивание возвращает новое значение уже в типе переменной. Это удобно для проверки переполнения: если записать в `int` число `4294967296`, результатом будет `0`, а для `4294967295` получится `-1`. Отладчик ведёт себя как настоящий компилятор, поэтому такие эксперименты показывают реальное поведение типов.
- Для `s21_size_t` и других беззнаковых типов будет обратная картина: отрицательные значения превратятся в огромные положительные.

## Стек вызовов

|Команда|Что делает|
|---|---|
|`bt`|показать стек вызовов|
|`bt all`|стеки всех потоков|
|`frame select 2`|перейти в кадр с номером 2|
|`up` / `down`|подняться или опуститься на кадр|
|`frame info`|сведения о текущем кадре|
|`frame variable`|переменные выбранного кадра|

Типичный сценарий при падении (segmentation fault): после остановки выполнить `bt`, найти свою функцию, перейти в её кадр и посмотреть переменные.

## Наблюдательные точки

Watchpoint останавливает программу в момент изменения значения.

|Команда|Что делает|
|---|---|
|`watchpoint set variable counter`|следить за переменной|
|`watchpoint set expression -- ptr`|следить за адресом|
|`watchpoint set variable -w read_write var`|реагировать на чтение и запись|
|`watchpoint list`|список наблюдений|
|`watchpoint delete 1`|удалить наблюдение|

Помогает найти место, где переменная неожиданно портится. Аппаратных наблюдательных точек ограниченное количество, поэтому следить можно лишь за несколькими значениями одновременно.

## Действия при срабатывании

Точке можно привязать команды, которые выполнятся автоматически:

```
br command add 1
> v i
> continue
> DONE
```

Так получается логирование без изменения исходного кода. Для простых случаев в VS Code достаточно логпоинтов (контекстное меню точки останова, пункт Add Logpoint).

## Типовые сценарии

Падение с segmentation fault:

- запустить под отладчиком и дождаться остановки
- выполнить `bt`
- перейти в кадр своей функции и посмотреть `v`
- проверить подозрительные указатели через `p ptr` и `p *ptr`

Выход за границы буфера:

- остановиться после вызова функции записи
- прочитать память вокруг буфера через `memory read`
- сравнить фактическую запись с ожидаемой

Неверный результат в цикле:

- поставить условную точку на нужную итерацию (`-c "i == 7"`)
- при необходимости пройти по шагам и сравнить значения

Переменная портится неизвестно где:

- поставить `watchpoint set variable` на неё
- продолжить выполнение и посмотреть, кто её изменил

Утечки памяти и обращения к освобождённой памяти отладчик не находит. Для этого подходят AddressSanitizer (`-fsanitize=address`) и Valgrind.

## Памятка

- Собирать с `-g -O0`.
- Для CodeLLDB команды с апострофом, для C/C++ от Microsoft префикс `-exec`.
- Смотреть переменные через `v`, вычислять выражения через `p`.
- Динамические массивы показывать через `expression -Z N -- ptr` или `memory read`.
- Падение — начинать с `bt`.
- Порча значения — ставить watchpoint.
- Неизвестная команда — `help` и `apropos`.
