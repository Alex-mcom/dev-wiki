# Этапы трансляции программы в машинный код

Процессор понимает только `машинный код` - это последовательность инструкций, записанная в виде шестадцатиричных чисел 

`Модуль` - исходный код программы `.c` 

Исходный код (.c) -> Препроцессор -> Предобработанный код (.i) -> Компилятор -> Ассемблерный код (.s) -> Ассемблер -> Объектный файл (.o) -> Линкер (компоновщик) -> Исполняемый файл

`Текстовый препроцессор` - обрабатывает директивы препроцессора в исходных файлах текстов программы.

`Компилятор` - отдельные файлы с текстами программы преобразует в машинный код, формируя **объектные файлы**. При компиляции компилятор выбирает ту архитектуру, под которой он запущен:

```bash
gcc -c main.c -o main.o  # Компиляция в объектный файл (машинный код)
```

`Линкер` - соединяет между собой объектные файлы, формируя единую программу, добавляет код запуска и коды используемых библиотечных функций

```bash
gcc main.o -o program  # Линковка
```

# Препроцессор
## \#include
Вставляет содержимое указанного файла на ее место

>Если нужно подключить стандартные файлы, поставляемые с компилятором языка Си, то следует писать угловые скобки. Если же подключаются свои собственные заголовочные файлы, то их имена следует заключать в двойные кавычки.

```c
#include "tmp/printf.h"
 
int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

### Директивы условной компиляции

| **Директива** |            | **Описание**                                                                                    |
| ------------- | ---------- | ----------------------------------------------------------------------------------------------- |
| `#if`         | expression | Проверка произвольного условия.                                                                 |
| `#else`       |            | Определение ветки «иначе».                                                                      |
| `#endif`      |            | Директива (метка) завершения фрагмента для условия.                                             |
| `#ifdef`      |            | Сокращение от if defined. Позволяет делать проверку на наличие макроимени в текущем модуле.     |
| `#ifndef`     | identifier | Сокращение от if !defined. Позволяет делать проверку на отсутствие макроимени в текущем модуле. |
| `#elif`       | expression | Сокращение от else if. Позволяет делать проверку по ветке «иначе».                              |
| `#elifdef`    | identifier | Сокращение от else if defined. Для реализации проверки наличия макроимени по ветке «иначе».     |
| `#elifndef`   | identifier | Сокращение от else if !defined. Для реализации проверки отсутствия макроимени по ветке «иначе». |
```
identifier -> макро-имена (SIZE, IS_CPP...)
expression -> выражение (SIZE + 1, (SIZE == 1)...)
```

В основном они используются, чтобы оставить или убрать определенный фрагмент текста программы в зависимости от какого-либо условия. Например, пишется программа, которую предполагается компилировать  с использованием компилятора Си, а также с использованием компилятора С++. Но в этих языках программирования имеются некоторые отличия в используемых конструкциях и часть программного кода должна различаться в зависимости от языка. Так вот, чтобы написать универсальный текст программы и иметь возможность компилировать его как Си, так и С++, можно воспользоваться условными директивами следующим образом:

>Директива `#ifdef` – это сокращенный вариант записи конструкции `#if defined`.

```cpp
#define LANG_C
 
#if defined(LANG_C)
#   include <stdio.h>
#else
#   include <iostream>
#endif
 
int main(void)
{
         int x=5;
#ifdef LANG_C
         printf("%d\n", x);
#else
         std::cout << x << std::endl;
#endif
 
    return 0;
}
```

Директивы условной компиляции `#if`, `#else`, `#endif` работают подобно условным операторам *if-else*, но с некоторыми отличиями. 

- в условиях директив можно использовать исключительно **целочисленные литералы** и **макроимена**. С этими элементами можно выполнять все булевы операции сравнения:

```
==, !=, <, >, <=, >=
```

логические связки:

```
&&, ||, !
```

все бинарные арифметические и битовые операции:

```
+, -, *, /, %, &, |, ^
```

и применять оператор `defined`, которые возвращает *1*, если указанное макроимя существует и *0* – в противном случае. 

>Никаких переменных, функций и прочих конструкций, значение которых определяется в процессе работы программы, здесь применять нельзя.

- Директивы условной компиляции не образуют своих собственных внутренних блоков. Поэтому для указания того, что попадает внутрь таких директив, в конце обязательно следует прописать директиву `#endif` – метку, означающую конец текущей директивы условной компиляции.
- Директивы препроцессора анализируют программу как текст (на уровне лексем). Это означает, что они не учитывают области видимости: локальные, глобальные и т.п. Поэтому все директивы принято записывать с самого начала строки (с левого края), в том числе при записи директив внутри функции `main()`

### Использование директив условной компиляции в заголовочных файлах

Если мы посмотрим на содержимое какого-либо стандартного заголовочного файла, например, того же `stdio.h`, то вначале увидим такие строчки:

```cpp
#ifndef _INC_STDIO
#define _INC_STDIO
```

А ниже обязательно будет записана директива:

```cpp
#endif
```

Это защита от повторного включения содержимого заголовочного файла в текущий модуль. Например, если мы в программе дважды напишем строчки:

```cpp
#include <stdio.h>
#include <stdio.h>
```

### Макрос-функции

>Во избежания неоднозначного поведения код макро-функций стоит писать в скобках!

```c
#include <stdio.h>
 
#define SQ_PR(A, B)   ((A) * (B))
 
int main(void)
{
    int res = SQ_PR(2, 3); // будет подставлено ((x + 2) * (y - 3))
    printf("res = %d\n", res);
 
    return 0;
}
```

### Операция \#

Операция `#` возвращает текстовое представление лексемы

```c
#include <stdio.h>
 
#define SQ_PR(A, B)     ((A) * (B))
#define TEXT(A, B)     "Square of rectangle (" #A ") x (" #B ")\n"
 
int main(void)
{
    int res = SQ_PR(2, 3);
    printf(TEXT(x-2, y-3)); // Square of rectangle (x-2) x (y-3)
 
    return 0;
}
```

Обратите внимание, программа была успешно скомпилирована и выполнена, несмотря на то, что в ней нет объявлений для *x* и *y*, которые были указаны в макровызове *TEXT(x-2, y-3)*. Макропроцессор выполняет обработку текста программы до синтаксического анализатора и до перевода программы непосредственно в машинный код. Поэтому фрагмент *TEXT(x-2, y-3)* заменяется на строку *«Square of rectangle (x-2) x (y-3)\n*», которая компилируется без каких-либо проблем.

### Операция \#\#

Оператор `##` берет аргумент слева и аргумент справа и соединяет их в единое имя переменной, функции или типа

```c
#include <stdio.h>

// Макрос создает переменную с указанным именем
#define MAKE_VAR(NAME, ID) int NAME ## _ ## ID = 100

int main(void) {
    MAKE_VAR(score, 1); // Препроцессор превратит это в: int score_1 = 100;
    
    printf("%d\n", score_1); // Выведет: 100
    return 0;
}
```

## \#undef

Если какой-либо макрос ранее был определен, то переопределить его с новым поведением уже не получится. Если все же это требуется сделать, то сначала нужно отменить прежний макрос и прописать новый. Для отмены макроопределений используется директива `#undef`, например, так:

```cpp
#define TEN     2 * FIVE
#undef TEN
#define TEN     10
```

# Статические и динамические библиотеки

**Динамическая библиотека** (или **shared library**) - это файл, содержащий готовые к выполнению машинные инструкции (функции, переменные и так далее), которые могут использоваться несколькими программами одновременно, **без включения их кода в каждый исполняемый файл**

На выходе получаем бинарник и файлы библиотек к нему.

⚙️ Расширения файлов динамических библиотек:
- Windows: `.dll` (Dynamic Link Library)
- Linux/Unix: `.so` (Shared Object)
- MacOS: `.dylib` или `.so`

Примеры директорий:
- Windows: `C:\Windows\System32`
- Linux: `/usr/lib`, `/usr/local/lib` или рядом с исполняемым файлом
- MacOS: `/usr/lib` или `/Library/Frameworks`


**Статическая библиотека** (`.lib`, `.a`) - скомпилированные объектные файлы, объединенные в один архив. Компилятор берет нужные файлы функции из этих библиотек и **встраивает их в исполняемый файл**. 

На выходе получаем один бинарник.

Плюсы статических библиотек:
1. Исполняемый файл не зависит от внешних библиотек
2. Работает быстрее за счёт отсутствия динамической нагрузки

Минусы статических библиотек:
1. Большой размер исполняемого файла
2. При обновлении библиотеки придется пересобирать программу

# Заголовочный файл

**Заголовочный файл** (с расширением `.h`) в C — это файл, который подключается к исходному коду через `#include` и содержит **объявления** интерфейса: прототипы функций, типы, макросы, константы и т.п. Сам по себе он не компилируется в отдельный объектный файл — препроцессор просто вставляет его содержимое в место `#include`.

Подключается через двойные кавычки:
```c
#include "my_header.h"
```

Обычно в заголовочном файле содержится:

**Прототипы функций:**
```c
int add(int a, int b);
```

**Определения типов:**
```c
typedef struct Point {
	int x;
	int y;
} Point;
```

**Макросы и константы:**
```c
#define PI 3.14159
```

**Объявления внешних переменных:**
```c
extern int global_counter;
```

**Include guards — защиту от повторного включения:**
Или нестандартный, но распространённый `#pragma once`
```c
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

// содержимое

#endif
```
