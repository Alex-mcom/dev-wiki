# Простые типы

Это встроенные в язык типы. Их имена **зарезервированы** компилятором и не могут быть переопределены:
```c
int, char, double, float, short, long, unsigned, signed, _Bool, void
```

Плюс производные от них:
```c
int*, char[10], double*
```

> [!Особенности]

- Имя типа — **одно и то же** в объявлении и в использовании.
- Не требуют никакого дополнительного ключевого слова при использовании
- Живут в **обычном пространстве имён** — конфликтуют с именами переменных и псевдонимами `typedef`.
```c
int main(void) {
    typedef int i32;
    int i32 = 1;  // ОШИБКА: redeclaration в одной области
    return 0;
}
```

---

В зависимости от разрядности процессора и ОС размер типов может меняться. Стандарты языка Си никак не оговаривают конкретные размеры типов данных. 

![[data_types_c.jpeg]]

`int`, записанный в квадратных скобках, означает, что  эти типы можно записывать как с `int` в конце, так и без него, например:

```cpp
short int a;
short b;
long d;
long int m;
```

Причем, от добавления слова `int` тип данных никак не меняется, поэтому в современной практике программирования на Си это ключевое слово совместно с модификаторами `short` и `long` не указывают, а пишут просто:

```cpp
short b;
long d;
```


## Модификаторы signed и unsigned

Когда мы в программе задаем переменную этого типа:

```cpp
char fl_view;
```

то в зависимости от компилятора она может принимать или целые числа в диапазоне [0; 255], или целые числа в диапазоне [-128; 127]. 

Существуют два модификатора, чтобы гарантировано указать тип переменной как беззнаковый или знаковый:

- `unsigned` – беззнаковый;
- `signed` – знаковый (появился в стандарте ANSI C90).

Если при объявлении явно указать:

```cpp
unsigned char fl_view;
```

то переменная fl_view будет описывать целые числа в интервале [0; 255]. Если же указать:

```cpp
signed char fl_view;
```

то переменная fl_view будет описывать целые числа со знаком в интервале [-128; 127].

Все остальные целочисленные типы (`short`, `int`, `long`, `long long`) по умолчанию **всегда идут как знаковые**. Поэтому определение вида:

```cpp
int arg;  // as signed
```

создает переменную *arg* как целочисленную и знаковую. И так со всеми другими типами, кроме `char`. Кстати, именно по этой причине в языке Си появился модификатор `signed`, чтобы гарантированно объявлять переменную типа `char` со знаком. У других целых типов модификатор `signed` указывать не имеет смысла, он идет по умолчанию. А вот второй модификатор `unsigned` вполне имеет смысл. Например:

```cpp
unsigned short d;
```

Получаем целочисленную беззнаковую переменную с именем *d*. И так со всеми целыми типами.

> Вещественные типы `float` и `double` **всегда знаковые** и применять к ним эти модификаторы нельзя!

## Целочисленные литералы

```c
int var = 100; // 100 - здесь это целочисленный литерал, ему тоже нужно где-то храниться, поэтому компилятор по умолчанию выделяет ему пространство типа int
```

>В программировании явно прописанные числовые значения называются **числовыми литералами** и представляется как целочисленная константа типа `int`. 

Так решил создатель языка Си Деннис Ритчи: все целочисленные константы, _записанные в программе в десятичном виде_, хранить на уровне типа `int`. Но только в том случае, если число умещается в диапазон этого типа. В современных 32- и 64-битных компьютерах тип `int`, как правило, составляет `4 байта` (32 бита) и описывает диапазон значений:[-2147483648; 2147483647]

Если целочисленный литерал положителен и не умещается в этот диапазон, то компилятор подбирает соответствующий размер типов данных в порядке возрастания:

`int`, `long`, `long long`

>Если же и самого большого недостаточно (что сложно себе представить в реальных задачах), то компилятор выдаст ошибку.

При желании мы можем явно указать компилятору тип числового литерала. Для этого используются следующие суффиксы:

- `U` или `u` – использование модификатора `unsigned` в определении литерала;
- `L` или `l` – использование типа `long` при определении литерала;
- `LL` или `ll` – использование типа `long long` при определении литерала.

```c
int dec_i, dec_ui, dec_l, dec_ul;
dec_i = 100;        // тип литерала int
dec_ui = 100U;      // тип литерала unsigned int
dec_l = 100L;       // тип литерала long
dec_ul = 100UL;     // тип литерала unsigned long

unsigned int a = 3000000000U; // Без 'U' компилятор пожалуется или попробует сделать long
long long b = 40000000000LL; // Без 'LL' компилятор может выдать предупреждение
```

>Эти суффиксы позволяют более точно контролировать поведении числовых литералов и избегать ошибок при автоматическом приведении типов
### Проблемы при явном приведение типов числовых литералов

Указание суффиксов вроде `U` (unsigned) или `L` / `LL` (long / long long) нужно для того, чтобы **принудительно задать тип самому литералу ДО того, как над ним начнутся какие-либо вычисления**.

>Компилятор определяет тип результата математического выражения **по типам его участников (операндов)**, а не по переменной, в которую вы этот результат записываете.

```c
long long microseconds = 1000000 * 3600; // Хотим получить микросекунды в часе (3 600 000 000)
```

- **Без суффикса:** Компилятор видит два литерала `1000000` и `3600`. Оба влезают в `int`, поэтому оба получают тип `int` (32 бита). Вычисление происходит в типе `int`, результат (3.6 млрд) **переполняет 32-битный `int`**, скручивается в отрицательное число, и только _потом_ этот испорченный `int` кастуется к `long long`.
    
- **С суффиксом `LL`:**

```c
long long microseconds = 1000000LL * 3600; 
```

Первый операнд сразу становится 64-битным `long long`. Второй операнд (`3600`) автоматически подтягивается к `long long`. Вся математика сразу выполняется в 64-битном регистре без промежуточного переполнения.

### Числовые литералы еще в шестнадцатеричной и восьмеричной форме

Язык Си позволяет определять в программе числовые литералы еще в **шестнадцатеричной** и **восьмеричной** форме. 

```c
int dec, hex, oct;
dec = 100;
hex = 0x1FA;
oct = 0123;
```

Здесь *100* – это десятичная форма записи; *0x1FA* – шестнадцатеричная (число *1FA*); *0123* – восьмеричная. То есть, для записи шестнадцатеричных чисел перед ними ставится префикс в виде символов `0x`, а для записи восьмеричных – префикс в виде `0`. Так можно прописывать любые числа в нужном нам формате. Разумеется, на уровне машинных кодов они представляются единым образом в виде набора бит и запись числовых литералов в той или иной форме служит исключительно для удобства восприятия программистом. Не более того.

Но с шестнадцатеричными и восьмеричными литералами есть один важный нюанс. Их компилятор изначально представляет типом `int`, как десятичные, а если не умещаются, то используются следующая последовательность:

`unsigned int`, `long`, `unsigned long`, `long long`, `unsigned long long`

## Символьные литералы

Символьные литералы на уровне компилятора воспринимаются как `int`

```c
char ch = 'd'; // 'd' хранится как int = 100 (код по ASCII)
```

## Вещественные литералы

```c
double d1, d2, d3, d4;
d1 = 10.0;
d2 = -7.;
d3 = 1e2;
d4 = 5e-3;
```

Несмотря на то, что числа *10.0* и *-7.0* с математической точки зрения соответствуют целым числам *10* и *-7*, на уровне программы они будут вещественными и иметь тип `double`.

>Все вещественные литералы компилятор языка Си по умолчанию представляет типом `double`. Соответственно, математические операции с числами *10.0* и *-7.0* будут выполняться несколько иначе, чем с аналогичными целыми числами.

Последние два варианта – запись числа в экспоненциальной форме:

`<число>e<степень десятки>`

```
1e2 = 1⋅10^2 = 100
5e-3 = 5⋅10^−3 = 0,005
```

Такую форму удобно использовать в научных расчетах, когда используются или очень маленькие или очень большие числа. В любом случае экспоненциальная форма переводится в вещественное число типа `double`, даже если оно математически является целым, а не дробным.

При желании мы можем явно указать компилятору переводить вещественный литерал в тип `float`. Для этого после числа следует прописать суффикс `f`, например, так:

```ini
d1 = 10.0f;
```

В такой записи вещественное число *10.0* будет представляться типом `float`, а не `double`. Это бывает полезно, когда используется переменная типа `float` и ей правильно было бы присвоить значение того же типа:

```nginx
float var_f;
var_f = 10.0f;
```

## Тип `char`

Все символьные литералы в программе автоматически переводятся в соответствующие коды: каждому символу ставится в соответствии определенный код (целое число). И приводил фрагмент таблицы `ASCII`. Компилятор, используя текущую кодовую таблицу (не обязательно ASCII), переводит все числа в соответствующие коды. 

```c
ch = 'd';

// в нашем конкретном случае, может быть заменена на:
ch = 100;
```

```perl
printf("ch = %c, code = %d\n", ch, ch);
// ch = d, code = 100
```

Этот факт показывает, что компьютеру важно лишь какое число хранится в переменной *ch*, а его интерпретация может быть самой разной: или как символ, или как целое число. Причем, обратите внимание, компилятор преобразовывает символьные литералы в числа типа `int`, а не `char`, как можно было бы ожидать. Это, как раз связано с тем, что он воспринимает любой символ, как десятичное число, а оно по умолчанию представляется типом `int`.

Конечно, при работе с символами мы формально можем использовать любой другой целочисленный тип. Например, прописать так:

```nginx
int ch;
ch = 'd';
```

Все же, если планируется в переменных хранить коды символов, то лучше использовать тип `char` в целях экономии памяти, т.к. этого типа достаточно для представления всех основных символов.

# Тегированные типы

Это `struct`, `union`, `enum`. Их имена называются **тегами** и живут в **отдельном пространстве имён**.

```c
struct Point { int x, y; };
union Value { int i; float f; };
enum Color { RED, GREEN, BLUE };
```

Здесь `Point`, `Value`, `Color` — **теги**, а не имена типов.


$$
Особенности
$$
- Чтобы использовать тег как тип, **нужно ключевое слово**:
```c
// объявления
struct Point { int x, y; };
union Value { int i; float f; };
enum Color { RED, GREEN, BLUE };

// использование
struct Point p;   // правильно
enum Color c;     // правильно
union Value v;    // правильно

Point p;          // ОШИБКА — Point это не тип, а тег
Color c;          // ОШИБКА
```

- Живут в **отдельном пространстве имён** — **не конфликтуют** с переменными и псевдонимами:
```c
int Point = 5;            // OK — переменная Point
struct Point p;           // OK — тег Point, отдельно
```
## `enum`

`enum` нужен там, где есть **фиксированный набор вариантов** — состояния, режимы, статусы, типы команд. Он превращает безликие числа в понятные имена и заставляет компилятор помогать вам искать ошибки. Это дёшево (ничего не стоит во время выполнения) и окупается с первого же рефакторинга.

```c
enum Color {
    RED,    // 0
    GREEN,  // 1
    BLUE    // 2
};
```

По умолчанию значения нумеруются с нуля. Можно задать явно:
```c
enum HttpStatus {
    HTTP_OK         = 200,
    HTTP_NOT_FOUND  = 404,
    HTTP_SERVER_ERR = 500
};
```

>Своя нумерация значений нужна, когда они используются во внешнем коде и есть чёткая привязка к значениям (совместимость с общепринятыми значения HTTP кодов, протоколами, публичными интерфейсами, битовые флаги и так далее).
>
>Если `enum` — чисто внутренний, значения никуда не сохраняются и не передаются, порядок не важен — можно писать без чисел.

```c
#include <stdio.h>

enum Light {
    LIGHT_RED,
    LIGHT_YELLOW,
    LIGHT_GREEN
};

void show_light(enum Light state) {
    switch (state) {
        case LIGHT_RED:    printf("Красный — стой\n");        break;
        case LIGHT_YELLOW: printf("Жёлтый — приготовься\n");  break;
        case LIGHT_GREEN:  printf("Зелёный — иди\n");         break;
    }
}

int main(void) {
    show_light(LIGHT_RED);
    show_light(LIGHT_GREEN);
    // show_light(5);  // сразу видно, что это чушь — глазом и ревьюером
    return 0;
}
```

### Способы объявления

**1. Объявление с тегом**
```c
enum Color {
    RED,
    GREEN,
    BLUE
};
```

Здесь `enum Color` — **тег** (имя типа). Использовать нужно с ключевым словом `enum`:
```c
enum Color c = RED;
enum Color palette[3] = { RED, GREEN, BLUE }; // массив из трёх элементов, где каждый элемент имеет тип enum Color.
```

**2. Анонимное перечисление (без тега)**
Используют, когда нужны просто именованные константы. Это альтернатива `#define`, но с областью видимости и отладкой.
```c
enum {
    BUFFER_SIZE = 1024,
    MAX_USERS   = 100
};

char buf[BUFFER_SIZE];
```

**3. `typedef` (псевдоним) + тег**
Комбинация, которая даёт и короткое имя, и тег:
```c
typedef enum Color {
    RED,
    GREEN,
    BLUE
} Color;

enum Color a = RED;   // через тег
Color b = GREEN;      // через псевдоним
```

**4. `typedef` (псевдоним) + анонимное перечисление (без тега)**
```c
typedef enum {
    RED,
    GREEN,
    BLUE
} Color;
```

Здесь у перечисления **нет тега**, только псевдоним `Color`. Использовать можно только:
```c
Color c = RED;        // OK
// enum Color c = RED;  // ОШИБКА — тега нет
```
### Примечания

- **Пространство имён.** Константы enum попадают в **глобальное пространство имён**, а не внутрь `Color`. То есть `RED`, а не `Color.RED`. Поэтому имена enum-значений должны быть уникальными в программе.
- **Альтернатива — `#define`.** Можно было бы использовать `#define RED 0`, но enum даёт тип, область видимости, отладку и группировку — поэтому предпочтительнее для наборов связанных констант.
- Можно комбинировать значения при инициализации:
  ```c
  enum Flags {
    A = 1,
    B,      // 2
    C = 10,
    D       // 11
  };
  ```

- Константы перечисления связаны с целыми числами и не имеют скрытого поведения, как например, директивы
```c
#define SQUARE(x) x * x

int main() {
    int a = 5;
    int b = SQUARE(a + 1); // Ожидаем (5+1)*(5+1) = 36
    printf("%d\n", b);       // Фактически получим 5 + 1 * 5 + 1 = 11
    return 0;
}
```

### `switch` без `default`

Компиляторы (GCC, Clang) умеют предупреждать, если в `switch` по enum обработаны не все значения:

```c
enum OrderStatus { ORDER_NEW, ORDER_PAID, ORDER_SHIPPED, ORDER_DELIVERED, ORDER_CANCELLED };

void describe(enum OrderStatus s) {
    switch (s) {
        case ORDER_NEW:       puts("Новый");       break;
        case ORDER_PAID:      puts("Оплачен");     break;
        case ORDER_SHIPPED:   puts("Отправлен");   break;
        case ORDER_DELIVERED: puts("Доставлен");   break;
        // забыли ORDER_CANCELLED
    }
}
```

С флагом `-Wswitch` (включён в `-Wall`) компилятор скажет:

```
warning: enumeration value 'ORDER_CANCELLED' not handled in switch
```

Это **бесплатный контроль полноты** — компилятор сам находит места, где вы забыли обработать новое состояние. С `#define` такое не работает.

## `struct`

**Структура (`struct`)** — это составной тип данных, объединяющий переменные разных типов под одним именем. В отличие от массива, элементы (поля) могут быть разных типов. Объявление структуры **не создаёт переменных** и **не выделяет память** — это лишь описание типа.

**Объявление структуры с тегом `tag_point`**
```c
struct tag_point {
    int x;
    int y;
    int z;
};
// x, y, z - имена полей внутри struct tag_point

...
// объявление переменной типа struct tag_point
struct tag_point point1;
```

**Объявление с использованием `typedef` (без тега):**
```c
typedef struct {
    char name[50];
    int age;
} Person;

...
// объявление переменной типа Person
Person p1;   // без слова struct
```

### Инициализация структур

**Позиционная (по порядку полей)**
```c
struct student {
    char name[20];
    char surname[20];
    int grade;
    int marks[20];
};

...

struct student student1 = {"Nicolay", "Strelnikov", 11, {4, 5, 4, 5, 3, 4}};

/* 
	grade и marks будут инициализировано нулями.
	Появятся предупреждения от компилятора
*/
struct student student2 = {"Nicolay", "Strelnikov"};
```

**designated initializers (с C99)**
```c
struct tag_point {
    int x;
    int y;
    int z;
};

...

struct tag_point pt = {.y = -1, .x = 2}; // z = 0
```

>В инициализаторе нельзя использовать массивы!

```c
struct person {
    char name[20];
    char sex;
};


char name_1[20] = "Alex";
// struct person p1 = {name_1, 'm'}; // ошибка

// либо
struct person p1;
strcpy(p1.name, name_1);

// либо частичная инициализация
struct person p1 = {.sex = 'm'};
strcpy(p1.name, name_1);

```
### Доступ к полям

**Через оператор `.` — для переменной структуры**
```c
struct tag_point {

pt.x = 1;
pt.y = 2;
pt.z = 3;
```

**Через оператор `->` — для указателя на структуру**
`->` — это оператор доступа к полю структуры **через указатель**.

Он объединяет две операции в одну:
1. **Разыменование указателя** (`*ptr`)
2. **Доступ к полю** (`.field`)

```c
указатель->поле

// Полностью эквивалентно:
(*указатель).поле

// Скобки вокруг *указатель обязательны, потому что `.` имеет более высокий приоритет, чем *
```

```c
struct Point {
    int x;
    int y;
};

struct Point p = {10, 20};
struct Point *ptr = &p;   // ptr — указатель на p

// Доступ через . (нужна переменная)
p.x = 5;          // ок: p — это сама структура

// Доступ через -> (нужен указатель)
ptr->x = 5;       // ок: ptr — указатель

// Эквивалентность
ptr->x = 5;
(*ptr).x = 5;     // то же самое
*ptr.x = 5;       // ❌ ОШИБКА! Это *(ptr.x), а у ptr нет поля x
```

>Оператор `->` упрощает чтение кода:

```c
(*(*node).next).data

// vs

node->next->data
```

**Изменение структуры через указатель**

```c
void isum_vector(struct tag_vector* v1, const struct tag_vector* v2) {
    v1->x += v2->x;
    v1->y += v2->y;
}
// вызов:
isum_vector(&bias, &one);
isum_vector(&bias, &(struct tag_vector){0.5, -0.5});
```
### Размер и выравнивание (padding)
Структура — абстракция; в машинных кодах её нет. При объявлении переменной выделяется **непрерывный участок памяти**, поля располагаются **по порядку**. Компилятор может добавлять **выравнивающие байты (alignment)** — чтобы данные попадали на чётные адреса (быстрее чтение).

Реальный размер структуры может **превышать сумму размеров полей**.

### Временный объект-структура

Удобно для передачи и возврата без создания переменных:
```c
struct tag_vector create_vector(double x, double y) {
    return (struct tag_vector) {x, y};
}
```
### Вложенные структуры
Структура может содержать в качестве элементов другие структуры.

```c
struct tag_fio {
    char name[20];
    char last[20];
};

struct tag_person {
    struct tag_fio fio;  // вложенная структура
    char sex;
    unsigned short old;
    char b_date[20];
};
```

**Инициализация**
```c
struct tag_person person = {
    {"Sergey", "Balakirev"},
    'M',
    98,
    "32.07.1925"
};
```

**Доступ к полям вложенной структуры:**
```c
printf("name: %s, last: %s\n", person.fio.name, person.fio.last);
// name: Sergey, last: Balakirev
```

**Изменение полей:**
```c
person.old = 17;
strcpy(person.b_date, "31.07.2006");  // для массивов — только strcpy!
strcpy(person.fio.name, "Sergiy");
```

>⚠️ Присваивание массиву строкового литерала напрямую — **ошибка**:
>`person.b_date = "31.07.2006";` — так нельзя.
>
>Хотя, в **инициализаторе** можно прописывать строковые литералы и они будут копироваться в соответствующие массивы. Но это отличия в работе инициализаторов и операции присваивания.

### Копирование структур
Переменные структур одного типа можно **присваивать друг другу** — копируется вся информация

- На уровне машинных кодов копируется **область памяти** целиком.
- Это **быстрее** и **удобнее**, чем копировать поля по отдельности.
- При изменении набора полей структуры код копирования **не требует правок**.
- **Массивы внутри структур тоже копируются**

```c
struct Point {
    int x;
    int y;
};

...
struct Point p1 = {12, -3};
struct Point p2 = p1;
```

### Массивы структур
- Каждый элемент массива — **структура**.
- Обращение: `figure[i].поле`.

```c
struct tag_point {
    double x, y, z;
};

int main(void) {
    struct tag_point figure[10];  // массив структур
    int figure_points = 0;
    
    figure[0].x = 1.2;
    figure[0].y = -5.6;
    figure[0].z = 10.0;
    
    figure[1].x = 12.4;
    figure[1].y = 3.2;
    figure[1].z = 7.6;
    
    figure_points = 2;
    return 0;
}
```

### Возврат структур из функций

>[!Возврат по значению (копирование)]
>
>**Минусы:** расход памяти стекового фрейма + копирование большого объёма данных.
>**Плюсы:** отсутствуют возможные утечки памяти

```c
struct tag_vector create_vector(double x, double y) {
    struct tag_vector v = {x, y};
    return v;
}

int main(void) {

	struct tag_vector res = create_vector(1.0, 2.0); // сюда копируется результат
}
```

---
>[!Возврат через указатель (malloc)]
>
>**Минусы:** потеря указателя и утечки памяти
>**Плюсы:** скорость и низкое потребление памяти
>
>Переходить на указатели стоит только когда копирование больших структур критично.

```c
struct tag_vector* create_vector(double x, double y) {
    struct tag_vector* v = malloc(sizeof(struct tag_vector));
    v->x = x; v->y = y;
    return v;
}

int main(void) {
	...
	struct tag_vector* ptr_res = create_vector(1.0, 2.0);
	...
	free(ptr_res); // не забываем освобождать память в конце
	return 0;
}
```

### Битовые поля

**Битовые поля** — это способ компактного хранения данных в структуре, при котором для каждого целочисленного поля явно указывается количество занимаемых бит.

- Данные выравниваются по длине `int` (обычно 4 байта = 32 бита).

```c
struct имя_структуры {
    unsigned имя_поля : количество_бит;
    ...
};
```

```c
struct date_time {
    unsigned day   : 5;   // 2^5 = 32 (макс. 31)
    unsigned month : 4;   // 2^4 = 16 (макс. 12)
    unsigned year  : 12;  // 2^12 = 4096 (макс. 4095)
    unsigned sec   : 6;   // 2^6 = 64 (макс. 59)
    unsigned min   : 6;   // 2^6 = 64 (макс. 59)
    unsigned hour  : 5;   // 2^5 = 32 (макс. 23)
};

// Суммарно: 5 + 4 + 12 + 6 + 6 + 5 = 38 бит
// 32 + 6 бит → округляется до 8 байт (два блока по 4 байта).
```

Работа с битовыми полями аналогична обычным структурам:
```c
int main(void) {
    struct date_time dt = {3, 5, 2023, 11, 7, 10};
    printf("%02d/%02d/%d %02d:%02d:%02d\n",
           dt.day, dt.month, dt.year, dt.hour, dt.min, dt.sec);
    return 0;
}
```

## `union`

**Объединение** (англ. _union_) — это составной тип данных, который позволяет хранить в одной и той же области памяти значения разных типов. Все члены объединения разделяют одну и ту же память.

В отличие от `struct`, где каждый член занимает **свою** память (размер структуры = сумма размеров членов + выравнивание), в `union` все члены **накладываются** друг на друга. Размер объединения равен размеру **самого большого** члена.

```c
union Data {
    int i;        // 4 байта
    float f;      // 4 байта
    char str[20]; // 20 байт
};

// sizeof(union Data) == 20
```

**Тегированные объединения** — вместе со `struct` и полем-тегом для отслеживания активного члена:

```c
#include <stdio.h>

typedef struct {
    enum { INT, FLOAT, PTR_S, NONE } type;
    union {
        int i;
        float f;
        char* s;
    } data;
} VAR;

void show_var(VAR v) {
    switch (v.type) {
        case INT:
            printf("%d\n", v.data.i);
            break;
        case FLOAT:
            printf("%.2f\n", v.data.f);
            break;
        case PTR_S:
            printf("%s\n", v.data.s);
            break;
        case NONE:
            printf("Значение отсутствует\n");
            break;
    }
}

int main(void) {
    VAR v1;

    v1.type = FLOAT;
    v1.data.f = 3.14;
    show_var(v1);

    v1.type = PTR_S;
    v1.data.s = "hello";
    show_var(v1);

    return 0;
}
```

# `typedef`-псевдонимы

Это имена, которые вы **сами создаёте** через `typedef`. Они становятся **полноценными именами типов**. Псевдоним — это **второе имя** для уже существующего типа. Он не создаёт ничего нового, только даёт короткий путь.

$$
Особенности
$$
- Используются **как обычный тип**, без ключевых слов:
```c
typedef int Number;               // Number = int
typedef struct Point Point;       // Point (без struct) = struct Point
typedef enum { RED, GREEN } Color; // Color = анонимный enum
typedef int (*BinOp)(int, int);   // BinOp = указатель на функцию

Number n = 5;
Point p;
Color c;
BinOp op;
```

- Живут в **обычном пространстве имён** — конфликтуют с переменными и другими псевдонимами
- **Не создают новый тип.** `Number` и `int` — это буквально одно и то же. Компилятор их не различает.

## `typedef`

Ключевое слово, которое создаёт **псевдоним** (новое имя) для существующего типа. Оно не создаёт новый тип, а просто позволяет называть уже существующий тип по-другому.

`typedef существующий_тип новое_имя;`

```c
typedef unsigned int uint;
typedef char* string;

uint x = 10;        // то же, что unsigned int x = 10;
string s = "hello"; // то же, что char* s = "hello";
```

**Сокращение длинных имён**
```c
typedef unsigned char      u8;
typedef unsigned short     u16;
typedef unsigned int       u32;
typedef unsigned long long u64;
```

**Переносимость (portability)**
```c
#ifdef _WIN64
    typedef unsigned long long size_type;
#else
    typedef unsigned long size_type;
#endif
```

**Упрощение записи указателей на функции**
```c
#include <stdio.h>

// Псевдоним для указателя на функцию: принимает два int, возвращает int
typedef int (*BinOp)(int, int);

int op_add(int a, int b) { return a + b; }
int op_sub(int a, int b) { return a - b; }
int op_mul(int a, int b) { return a * b; }

// Функция, принимающая указатель на операцию и применяющая её к массиву
int reduce(const int* arr, size_t n, BinOp op, int init) {
    int acc = init;
    for (size_t i = 0; i < n; i++) {
        acc = op(acc, arr[i]);   // вызов через указатель
    }
    return acc;
}

int main(void) {
    int data[] = {1, 2, 3, 4, 5};
    size_t n = sizeof(data) / sizeof(data[0]);

    // Один и тот же reduce — разные операции
    printf("Сумма:      %d\n", reduce(data, n, op_add, 0));
    printf("Разность:   %d\n", reduce(data, n, op_sub, 0));
    printf("Произвед.:  %d\n", reduce(data, n, op_mul, 1));

    // Массив указателей — тоже тип BinOp
    BinOp ops[] = {op_add, op_sub, op_mul};
    const char* names[] = {"add", "sub", "mul"};

    for (size_t i = 0; i < 3; i++) {
        printf("%s(10, 3) = %d\n", names[i], ops[i](10, 3));
    }

    return 0;
}
```

### Примечания

- typedef и указатели — распространённая ловушка
```c
typedef char* string;
string a, b;    // ОБА — char*. То же, что: char *a, *b;
```

Но:
```c
typedef char* string;
const string s;   // это char* const s, а НЕ const char* s!
```

Потому что `const` применяется к псевдониму целиком, а не к `char`. То есть `s` — константный указатель, но данные по нему можно менять. 


- `typedef` обрабатывается компилятором, а `#define` — препроцессором. `typedef` уважает области видимости, работает с отладчиком, не ломается на запятых.
```c
#define PINT int*
typedef int* pint;

PINT a, b;   // a — int*, b — int  (!) препроцессор просто подставил текст
pint a, b;   // a и b — оба int*  (нормально)
```
