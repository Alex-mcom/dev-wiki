# Стек

Стек (ADT, abstract data type) — это абстрактная структура данных с определённым набором операций и LIFO поведением.

LIFO (Last In First Out) - «последним пришёл — первым вышел».

Операции стека:
- `push` — положить наверх
- `pop` — снять сверху
- `peek`/`top` — посмотреть верх
- `is_empty`, `size` (опционально)

**Где используется:**
- DFS (поиск в глубину) — рекурсия **и есть** стек вызовов;
- отмена действий (Ctrl+Z);
- проверка скобок на баланс;
- вычисление выражений (обратная польская запись).

## Реализации

### Односвязный список

Узлы в куче, каждый ссылается на следующий, `top` указывает на вершину.

**Плюсы:**
- Размер ограничен только памятью (растёт и сжимается динамически).
- Нет «переполнения» в привычном смысле.
- O(1) на все операции.

**Минусы:**
- Каждый узел — отдельный `malloc` (медленно + фрагментация).
- Накладные расходы памяти на указатель в каждом узле.
- Плохая локальность кэша (узлы разбросаны по куче).
- Нужно аккуратно освобождать.

**Когда использовать:** когда размер заранее неизвестен и сильно меняется; в учебных целях; когда элементы «большие» и важнее простота, чем скорость.

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct tag_obj {
    int data;
    struct tag_obj* next;
} OBJ;

OBJ* push(OBJ* top, int data) {
    OBJ* next_obj = malloc(sizeof(OBJ));
    next_obj->data = data;
    next_obj->next = top;

    return next_obj;
}

OBJ* pop(OBJ* top, int* out) {
    if (top == NULL) return NULL;

    *out = top->data;
    OBJ* prev_obj = top->next;

    free(top);

    return prev_obj;
}

void show(const OBJ* top) {
    const OBJ* prev_obj = top;

    while (prev_obj != NULL) {
        printf("%d\n", prev_obj->data);
        prev_obj = prev_obj->next;
    }
}

OBJ* free_all(OBJ* top) {
    while (top != NULL) {
        OBJ* prev_obj = top->next;
        free(top);
        top = prev_obj;
    }

    return NULL;
}

int main(void) {
    OBJ* top = NULL;

    top = push(top, 0);
    top = push(top, 1);
    top = push(top, 2);

    show(top);

    int res;
    top = pop(top, &res);
    top = pop(top, &res);

    show(top);
    
    top = free_all(top);

    return 0;
}
```

### Динамический массив (vector)

Есть буфер фиксированной ёмкости + счётчик `size`. Когда места не хватает — **реаллоцируешь**буфер вдвое больше и копируешь.

```
push:  arr[size++] = x;  (если size == capacity → realloc)
pop:   return arr[--size];
```

**Плюсы:**
- Отличная локальность кэша — все элементы в одном непрерывном блоке.
- Нет накладных расходов на указатель в каждом узле.
- Один `malloc` вместо N.

**Минусы:**
- Амортизированно O(1) на push, но **отдельные** push могут быть O(n) из-за `realloc` + копирования.
- Нужна стратегия роста (обычно ×2) — иначе будет O(n²).
- В пике может держать вдвое больше памяти, чем реально нужно.

**Когда использовать:** **почти всегда**, когда элементы — простые типы или небольшие структуры, и важна скорость. Это самый частый выбор в реальном коде. `std::vector` в C++ внутри — это оно.

### Массив фиксированного размера

```
int buf[100];
int size = 0;
```

**Плюсы:**
- Простейший код, ноль `malloc`.
- Максимально быстрый.

**Минусы:**
- Размер известен заранее и жёстко ограничен.
- Переполнение нужно обрабатывать руками.

**Когда использовать:** встраиваемые системы, где динамическая память запрещена; когда верхняя граница размера точно известна; парсеры, рекурсивные алгоритмы с ограниченной глубиной.


# Очередь

**Принцип: FIFO** — _First In, First Out_ («первым пришёл — первым вышел»).

**Операции:**
- `enqueue` (push) — добавить **в конец** (**tail** (хвост) очереди)
- `dequeue` (pop) — взять **из начала** (**head** (голова) очереди)

**Где используется:**
- BFS (поиск в ширину) — **ваш случай**;
- планировщик задач в ОС;
- буфер печати;
- обработка сообщений.


- **`head`** — «голова»: отсюда **читаем** (dequeue).
- **`tail`** — «хвост»: сюда **пишем** (enqueue).
- Элементы живут между ними: `queue[head] ... queue[tail-1]`.
- Длина очереди = `tail - head`.
- `head == tail` → пусто.
