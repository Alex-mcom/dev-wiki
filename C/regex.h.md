В C для работы с регулярными выражениями используется POSIX-библиотека `<regex.h>`. Эта библиотека широко поддерживается, в том числе в musl, что делает её надежным выбором для переносимого кода на C.

Однако библиотека не поддерживает некоторые современные возможности, такие как ленивые квантификаторы или lookaround. Если вам нужен более мощный и знакомый синтаксис (как в Perl, Python, PCRE), можно использовать библиотеку **PCRE (Perl Compatible Regular Expressions)**.

```c
#include <stdio.h>
#include <stdlib.h>
#include <regex.h>

int main() {
	/* Хранит скомпилированный шаблон поиска */
    regex_t regex;
    
    /* Результат компиляции/поиска */
    int reti;
    
    char *pattern = "abc";
    char *string = "abcdef";

    // 1. Компиляция регулярного выражения
    reti = regcomp(&regex, pattern, 0); // 0 = базовый синтаксис POSIX
    if (reti) {
        fprintf(stderr, "Не удалось скомпилировать регулярное выражение\n");
        exit(1);
    }

    // 2. Выполнение поиска
    reti = regexec(&regex, string, 0, NULL, 0);
    if (!reti) {
        printf("Совпадение найдено.\n");
    } else if (reti == REG_NOMATCH) {
        printf("Совпадений не найдено.\n");
    } else {
        char errbuf[100];
        regerror(reti, &regex, errbuf, sizeof(errbuf));
        fprintf(stderr, "Ошибка при поиске: %s\n", errbuf);
    }

    // 3. Освобождение ресурсов
    regfree(&regex);
    return 0;
}
```

## `regcomp()`

```c
int regcomp(regex_t *preg, const char *regex, int cflags)
```

Компилирует строку регулярного выражения в специальный формат, пригодный для последующего поиска.

- **Параметры:**
    - `preg`: Указатель на структуру `regex_t`, в которую будет помещен скомпилированный шаблон.
    - `regex`: Указатель на строку с регулярным выражением, завершающуюся нулевым символом.
    - `cflags`: Побитовая комбинация флагов компиляции.

- **Возвращаемое значение:** `0` при успехе. В случае ошибки возвращается ненулевой код (например, `REG_BADPAT`, `REG_EPAREN`, `REG_ESPACE`), который можно расшифровать с помощью `regerror()`


```c
regex_t regex;
int reti; // Результат вызова функции
char *pattern = "abc";
char *string = "abcdef";

// Компиляция регулярного выражения
reti = regcomp(&regex, pattern, REG_EXTENDED);

if (reti) {
	fprintf(stderr, "Не удалось скомпилировать регулярное выражение\n");
	exit(1);
}
```

### `cflags`

`cflags` в `regcomp` — это набор флагов, которые кардинально меняют то, как интерпретируется сам шаблон и как впоследствии будет работать поиск.

Флаги комбинируются с помощью побитового ИЛИ (`|`), что позволяет включать несколько режимов одновременно.

```c
// Расширенный синтаксис + игнорирование регистра + многострочный режим
int cflags = REG_EXTENDED | REG_ICASE | REG_NEWLINE;
regcomp(&regex, "^hello", cflags);
```

#### `REG_EXTENDED`: Синтаксис регулярного выражения

Определяет, какой синтаксис использовать для шаблона. Поэтому для большинства современных задач рекомендуется всегда использовать `REG_EXTENDED`.

- **Без флага (по умолчанию):** Используется **Базовый** синтаксис регулярных выражений POSIX (BRE). В нем многие специальные символы, такие как `+`, `?`, `|`, `(`, `)`, `{`, `}` теряют свое мета-значение и воспринимаются буквально, если перед ними не стоит обратный слэш `\`. Например, чтобы выразить "одно или более вхождений", нужно писать `a\+`.
- **С флагом `REG_EXTENDED`:** Используется **Расширенный** синтаксис (ERE). Это тот синтаксис, к которому большинство из нас привыкло по Python, JavaScript и другим языкам. Символы `+`, `?`, `|`, `()`, `{}` являются мета-символами по умолчанию.

```c
// Базовый синтаксис (BRE): ищем "a" или "b"
regcomp(&regex, "a\\|b", 0); // Обратите внимание на двойной слэш

// Расширенный синтаксис (ERE): ищем "a" или "b"
regcomp(&regex, "a|b", REG_EXTENDED); // Проще и привычнее
```

#### `REG_ENHANCED` (только для `mac`)

Этот флаг не заменяет выбранный режим, а добавляет расширения поверх него. Он доступен только в macOS. В BRE при его использовании начинают работать конструкции вроде `\+`, `\?`, `|`, а также `\d`, `\s`, `\w`, нежадные квантификаторы `*?`, `+?` и другие расширения.

`REG_EXTENDED` меняет базовый синтаксис BRE на ERE, а `REG_ENHANCED` расширяет уже выбранный режим дополнительными возможностями, но только на macOS.

Флаги независимы: `REG_EXTENDED` меняет режим, `REG_ENHANCED` только расширяет его. Можно использовать их вместе, как в коде выше.

```c
int cflags = 0;
#ifdef REG_ENHANCED
cflags |= REG_ENHANCED;  /* только macOS, на Linux этой константы нет */
#endif
if (opts->extended) cflags |= REG_EXTENDED;

/* ... дальше как было ... */
reti = regcomp(&regex_list->patterns[i], strlen(p) ? p : "\\(\\)", cflags);
```
#### `REG_ICASE`: Игнорирование регистра

Делает поиск нечувствительным к регистру символов.

- **Без флага:** Поиск по шаблону `"Hello"` найдет только `"Hello"`.
- **С флагом `REG_ICASE`:** Поиск по шаблону `"Hello"` найдет `"Hello"`, `"hello"`, `"HELLO"` и т.д.

```c
// Поиск без учета регистра
regcomp(&regex, "hello", REG_EXTENDED | REG_ICASE);
```

#### `REG_NOSUB`: Оптимизация для проверки "есть/нет"

Сообщает функции `regcomp`, что вам не нужно знать, **где именно** находится совпадение, а только **факт** его наличия.

- **Эффект:** Когда `regexec` вызывается с шаблоном, скомпилированным с этим флагом, она игнорирует аргументы `nmatch` и `pmatch`. Это позволяет библиотеке не тратить ресурсы на вычисление и сохранение позиций совпадений, что может дать небольшой прирост производительности.
- **Использование:** Идеально подходит для задач валидации (например, "является ли эта строка email-адресом?"), где нужен только ответ "да" или "нет".

#### `REG_NEWLINE`: Многострочный режим

Изменяет поведение якорей `^` и `$`, а также классов символов при работе с текстом, содержащим символы новой строки (`\n`). Он заставляет библиотеку рассматривать строку как набор отдельных строк.

- **Что меняется с `REG_NEWLINE`:**
    1. **Символ `.` (точка)** перестает совпадать с `\n`. Теперь она соответствует любому символу, _кроме_ новой строки.
    2. **Класс `[^...]`** (любой символ, кроме перечисленных) также перестает совпадать с `\n`.
    3. **Якорь `^`** совпадает не только с началом всей строки, но и с позицией сразу после любого `\n`.
    4. **Якорь `$`** совпадает не только с концом всей строки, но и с позицией прямо перед любым `\n`.

- **Без флага (по умолчанию):** Символ `\n` воспринимается как обычный символ. Точка `.` будет совпадать с ним, а якоря `^` и `$` будут реагировать только на самое начало и самый конец строки.    

```c
// Строка "first\nsecond"
char *text = "first\nsecond";

// Без REG_NEWLINE: шаблон "first.second" НАЙДЕТ совпадение,
// потому что '.' совпадает с '\n'
regcomp(&regex, "first.second", REG_EXTENDED);

// С REG_NEWLINE: шаблон "first.second" НЕ НАЙДЕТ совпадение,
// потому что '.' больше не совпадает с '\n'
regcomp(&regex, "first.second", REG_EXTENDED | REG_NEWLINE);

// С REG_NEWLINE: шаблон "^second" НАЙДЕТ совпадение,
// потому что '^' теперь совпадает с началом новой строки после '\n'
regcomp(&regex, "^second", REG_EXTENDED | REG_NEWLINE);
```

## `regexec()`

```c
int regexec(const regex_t *preg, const char *string, size_t nmatch, regmatch_t pmatch[], int eflags)
```

Выполняет поиск скомпилированного шаблона в заданной строке. Требует обязательно `C-строку` на вход (конец строки - `\0`)

- **Параметры:**
    - `preg`: Указатель на структуру `regex_t`, инициализированную `regcomp()`, в которой описывается скомпилированный шаблон.
    - `string`: Строка, в которой выполняется поиск.
    - `nmatch`: Количество элементов в массиве `pmatch`.
    - `pmatch`: Массив структур `regmatch_t`, в который будут записаны позиции совпадений. Если `nmatch` равно `0` или был установлен флаг `REG_NOSUB`, этот параметр игнорируется.
    - `eflags`: Флаги выполнения. Обычно `0`, но могут быть `REG_NOTBOL` (не считать начало строки началом строки) и `REG_NOTEOL` (не считать конец строки концом строки).
        
- **Возвращаемое значение:** `0` при успешном совпадении, `REG_NOMATCH` (обычно `1`), если совпадений не найдено. Другие значения указывают на ошибку


```c
// Выполнение поиска
reti = regexec(&regex, string, 0, NULL, 0);

if (!reti) {
	printf("Совпадение найдено.\n");
} else if (reti == REG_NOMATCH) {
	printf("Совпадений не найдено.\n");
} else {
	char errbuf[100];
	regerror(reti, &regex, errbuf, sizeof(errbuf));
	fprintf(stderr, "Ошибка при поиске: %s\n", errbuf);
}
```
### `eflags`

`eflags` в `regexec()` — это набор битовых флагов, которые управляют **контекстом выполнения поиска**. В отличие от `cflags` (которые задают синтаксис и поведение самого шаблона при компиляции), `eflags` влияют на то, как `regexec` интерпретирует **границы** переданной строки в момент вызова.

#### `REG_NOTBOL`: (Not Beginning Of Line)

Этот флаг сообщает `regexec()`, что **начало переданной строки не является началом логической строки** (или просто: "не считай `^` началом строки").

Он критически важен при **итеративном поиске** нескольких совпадений в одной строке. Когда вы находите первое совпадение и хотите продолжить поиск со смещения, вы передаете в `regexec()` не исходную строку, а её "хвост" (указатель `string + offset`). Без флага `REG_NOTBOL` символ `^` в шаблоне будет ошибочно совпадать с началом этого "хвоста", хотя на самом деле это середина исходной строки.

**Пример использования (как в `grep -o`):**    
```c
const char *text = "foo bar foo";
const char *pattern = "^foo"; // Ищем "foo" только в начале строки
regmatch_t m;

// Первый вызов: ^ совпадает с началом text
regexec(&regex, text, 1, &m, 0); // Найдет "foo" в начале

// Второй вызов: ищем со смещения, передаем REG_NOTBOL
regexec(&regex, text + m.rm_eo, 1, &m, REG_NOTBOL); // НЕ найдет "foo" в середине
```

Без `REG_NOTBOL` второй вызов нашел бы "foo" в середине строки, что было бы неверно.    

#### `REG_NOTEOL`: (Not End Of Line)

Этот флаг работает аналогично, но для конца строки: он сообщает, что **конец переданной строки не является концом логической строки** ("не считай `$` концом строки").

Ситуация, симметричная `REG_NOTBOL`. Если вы анализируете часть строки, которая не является её концом, флаг `REG_NOTEOL` предотвратит ложное срабатывание якоря `$`. Это может быть полезно, например, при потоковой обработке данных, когда вы уверены, что за текущим буфером последуют другие данные

### Группы (`pmatch`)

**Группа** (capture group, захватывающая группа) — это часть шаблона, заключённая в круглые скобки `(...)`. Скобки делают две вещи одновременно, и это стоит запомнить как единый факт:

1. **Группируют** — позволяют применить квантификатор (`*`, `+`, `?`, `{n,m}`) или альтернативу `|`к целой последовательности, а не к одному символу.
2. **Захватывают** — сохраняют найденный фрагмент отдельно, чтобы вы могли его потом извлечь по номеру.

#### Роль 1: группировка (без извлечения)

Без скобок квантификатор применяется к **одному** предыдущему символу:
```c
// Шаблон: "ab+"  → "a", затем один или более "b"
// Совпадёт с: "ab", "abb", "abbb"
// НЕ совпадёт с: "abab"
```

Со скобками квантификатор применяется ко **всей последовательности**:
```c
// Шаблон: "(ab)+" → одна или более последовательностей "ab"
// Совпадёт с: "ab", "abab", "ababab"
// НЕ совпадёт с: "abb"
```

#### Роль 2: захват (извлечение)

```c
const char *pattern = "(\\d{4})-(\\d{2})-(\\d{2})";
const char *text = "Дата: 2026-10-24";
regmatch_t pmatch[4];
regexec(&regex, text, 4, pmatch, 0);

// pmatch[0] → "2026-10-24"  (всё совпадение)
// pmatch[1] → "2026"        (группа 1 — год)
// pmatch[2] → "10"          (группа 2 — месяц)
// pmatch[3] → "24"          (группа 3 — день)
```

Один и тот же шаблон одновременно **сгруппировал** три части даты и **захватил** каждую в отдельный слот. Без скобок вы бы получили только `pmatch[0] = "2026-10-24"` и должны были бы вручную резать строку по дефисам.

Практически любая задача «вытащить структуру из текста» требует групп. Именно поэтому `nmatch` и `pmatch` существуют — без групп они были бы не нужны, хватило бы булева результата.

>Однако применимо к `grep`, где задача просто показать: есть ли совпадение в строке или нет, **группы использовать не нужно**. Кроме, пожалуй, флага `-o` (вывести только совпавшую часть строки), в этом случае `nmatch=1` (показывает всё совпадение целиком) покажем покажет нам позиции начало и конца совпадения через структуру **`regmatch_t`**: `rm_so` и `rm_eo`


### Структура **`regmatch_t`**

```c
typedef struct {
    regoff_t rm_so; // Начальное смещение (байт) от начала строки
    regoff_t rm_eo; // Конечное смещение (байт), указывает на символ после совпадения
} regmatch_t;
```

- `pmatch[0]` всегда содержит позицию **всего совпадения целиком.**
- `pmatch[1]`, `pmatch[2]`, ... содержат позиции для подвыражений, заключенных в скобки `(...)`.


## `regfree()`

```c
void regfree(regex_t *preg)
```

Освобождает память, выделенную функцией `regcomp()` для скомпилированного шаблона. Эту функцию необходимо вызывать после завершения работы с шаблоном, чтобы избежать утечек памяти.

- **Параметры:**
    - `preg`: Указатель на структуру `regex_t`, которая была ранее инициализирована `regcomp()`.


```c
regfree(&regex);
```
