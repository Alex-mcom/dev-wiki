`make` — утилита автоматизации сборки. Читает файл `Makefile` , определяет, какие файлы устарели относительно своих зависимостей, и выполняет только необходимые команды. Основной сценарий — сборка C/C++-проектов, но применима к любому языку и любым задачам (генерация документации, запуск тестов, деплой).

Ключевая идея: **временные метки**. Если цель (target) старше любой своей зависимости  — цель надо обновить, выполнив рецепт (recipe).

**Как make обрабатывает Makefile**
1. Читает файл целиком, запоминает все правила и переменные.
2. Берёт **первую цель** в файле (цель по умолчанию) — обычно `all`.
3. Рекурсивно проверяет её зависимости: для каждой ищет правило и проверяет его зависимости, и так до файлов, которые уже есть и не имеют правил (обычно `.c`, `.h`).
4. Выполняет рецепты **в порядке снизу вверх** — сначала самые глубокие зависимости, потом цель.

>Порядок правил в файле **не важен** для выполнения — важен только порядок для выбора цели по умолчанию.

## Правила
### Структура правила

>Строка рецепта начинается с **символа табуляции**, не с пробелов

```makefile
цель: зависимость1 зависимость2 ...
<TAB>рецепт
```

- **цель** — файл, который создаём (или фиктивное имя действия);
- **зависимости** — файлы, от которых цель зависит, через пробел;
- **рецепт** — команды обновления цели.

### 1. Шаблонные правила (с рецептом)

```makefile
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
```

`%` — подстановочный знак, «любая часть имени». Одно правило обслуживает все пары `.c → .o`. Когда `make` нужен `foo.o`, он подставляет `% = foo`, получает зависимость `foo.c`, выполняет рецепт.

**Важно:** `%` в цели и `%` в зависимости — **одна и та же** часть. Поэтому `foo.o` требует именно `foo.c`, а не любой `.c`.

Шаблон описывает **рецепт**, но **не знает**, от каких заголовков зависит `.c`. Для полных зависимостей нужны либо явные правила, либо `-MMD -MP`

### 2. Явные правила (без рецепта)

```makefile
main.o: main.c util.h config.h
util.o: util.c util.h

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
```

Явное правило `main.o: ...` задаёт **зависимости**, шаблон — **рецепт** (в явной строке рецепта нет). `make` объединяет: полный список зависимостей + рецепт из шаблона.

**Приоритет:** если для цели есть явное правило, оно используется; шаблон применяется, только если явного нет. Если явное правило без рецепта — рецепт берётся из шаблона.

**Заголовки в явных правилах нужны только `make`**, в команду `gcc` они не попадают: `$<` в шаблоне — это `.c`, а `$^` в шаблоне видит только `%.c`. Заголовки `gcc` подтянет сам через `#include`.

### 3. Явные правила (с рецептом) — самодостаточные

```makefile
main.o: main.c util.h config.h
	gcc -Wall -g -c main.c -o main.o
```

Здесь `main.o` — цель, три зависимости, и **свой рецепт** прямо в правиле. `make` для `main.o`возьмёт именно это правило и этот рецепт. Шаблон `%.o: %.c` для `main.o` даже не будет рассматриваться — **явное правило имеет приоритет**.

## Переменные

```makefile
# ============================================================
#  Инструменты и флаги
# ============================================================
CC       = gcc
CFLAGS   = -Wall -Wextra -g
LDFLAGS  =
LDLIBS   =

# ============================================================
#  Файлы
# ============================================================
TARGET   = s21_cat
SRCS     = main.c util.c parser.c
OBJS     = $(SRCS:.c=.o)
```

- обращение: `$(ИМЯ)`;
- `=` — рекурсивное присваивание (значение вычисляется при использовании);
- `:=` — немедленное (вычисляется сразу);
- `?=` — присвоить, только если переменная ещё не задана;
- `+=` — дописать в конец.

### Общепринятые переменные

| Переменная | Что содержит                             | Кому передаётся               | Пример                         |
| ---------- | ---------------------------------------- | ----------------------------- | ------------------------------ |
| `CC`       | компилятор C                             | `gcc`, `clang`, `cc`          | `CC = gcc`                     |
| `CXX`      | компилятор C++                           | `g++`, `clang++`              | `CXX = g++`                    |
| `CPPFLAGS` | флаги **препроцессора** (C PreProcessor) | `-I`, `-D`, `-U`              | `CPPFLAGS = -Iinclude -DDEBUG` |
| `CFLAGS`   | флаги **компилятора C**                  | `-Wall`, `-g`, `-O2`, `-std=` | `CFLAGS = -Wall -Wextra -g`    |
| `LDFLAGS`  | флаги **линковщика**                     | `-L`, `-Wl,`, `-static`       | `LDFLAGS = -L/usr/local/lib`   |
| `LDLIBS`   | **библиотеки** для линковки              | `-l`, `-lm`, `-lpthread`      | `LDLIBS = -lm -lpthread`       |

### Автоматические переменные

Заполняются `make` для каждого правила перед выполнением рецепта.

|Переменная|Значение|Пример для `main.o: main.c util.h`|
|---|---|---|
|`$@`|имя цели|`main.o`|
|`$<`|первая зависимость (левая в списке)|`main.c`|
|`$^`|все зависимости без дубликатов|`main.c util.h`|
|`$+`|все зависимости с дубликатами|`main.c util.h`|
|`$?`|зависимости новее цели|`main.c` (если изменён)|
|`$*`|стебель (часть, совпавшая с `%`)|`main`|

Однобуквенные автоматические переменные пишутся **без скобок**: `$@`, `$<`. Обычные — со скобками: `$(CC)`.

**Когда что использовать:**

- компиляция — `$<` (один вход);
- линковка — `$^` (все входы);
- имя результата — `$@`.

**«Первая» = «левая».** Порядок в строке зависимостей значим для `$<`. Поэтому в правиле компиляции пишут `%.o: %.c`, а не `%.o: util.h %.c`.


## Цели

**Цель (target)** — это то, что стоит **слева от двоеточия** в правиле. Формально это имя, которое `make` пытается «получить». Цель бывает двух принципиально разных видов:

|Вид|Что это|Пример|
|---|---|---|
|**Файловая цель**|реальный файл на диске, который создаёт рецепт|`main.o`, `s21_cat`|
|**Фиктивная цель (phony)**|имя действия, файла не создаёт|`all`, `clean`, `test`|

`make` по умолчанию считает **любую** цель файлом и проверяет её существование и время модификации. Именно поэтому фиктивные цели объявляют через `.PHONY` — чтобы `make` не искал одноимённый файл.

### Файловые цели

Это цели, которые соответствуют артефактам сборки. В типичном C-проекте их три уровня:

```text
s21_cat        ← исполняемый файл (линковка)
├── main.o     ← объектный файл (компиляция)
│   └── main.c ← исходник (существует изначально)
├── util.o
│   └── util.c
└── parser.o
    └── parser.c
```

Каждый уровень — отдельная цель со своим правилом:

```makefile
# Уровень 3: исполняемый файл
s21_cat: main.o util.o parser.o
	$(CC) $^ -o $@
	
# Уровень 2: объектные файлы
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
	
# Уровень 1: .c и .h — уже есть, правил нет
```

#### Компиляция

Компиляция позволяет из `.c` файлов получить `.o` файлы. Важно уточнить, что это ещё не готовый бинарник, который можно запустить. Исполняемый файл получается после линковки. 

**Зачем вообще `.o`, а не компилировать сразу в бинарник**
1. **Инкрементальность.** Меняете один `.c` — перекомпилируется только его `.o`, остальные не трогаются. Линковка быстрая.
2. **Раздельная компиляция.** Разные `.c` могут компилироваться параллельно (`make -j`).
3. **Модульность.** Один `.o` можно использовать в разных программах/библиотеках.
4. **Кэширование.** Если `.o` не изменился, его не надо пересобирать даже при смене флагов линковки.

##### Шаблонное правило для всех `.c` файлов

```makefile
%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@
```

- `%.o: %.c` — шаблон: любой `X.o` из `X.c`;
- `$<` — первый вход, то есть `X.c`;
- `$@` — выход, то есть `X.o`;
- `-c` — «compile only»: препроцессинг + компиляция + ассемблирование, **без линковки**.

Один вызов `gcc -c` делает три внутренних шага:

```text
main.c ──cpp──► main.i ──cc1──► main.s ──as──► main.o
```

##### Зависимости для `.o` файлов

Существуют несколько способов задать зависимости для корректной компиляции `.o` файла:

**Явные строки для каждого `.o`:**
>Зависимости — из явной строки, рецепт — из шаблона. Ручная поддержка, легко забыть.

```makefile
main.o:   main.c   util.h config.h
util.o:   util.c   util.h
parser.o: parser.c parser.h config.h
```
---
**Автогенерация `-MMD -MP` (рекомендуется):**
>`gcc` при компиляции сам создаёт `main.d` со списком заголовков, `-include` его подхватывает. Ручные строки не нужны.

```makefile
CFLAGS = -Wall -g -MMD -MP
DEPS   = $(OBJS:.o=.d)
-include $(DEPS)
```

##### Явные правила для отдельных `.o` файлов

Иногда для конкретного файла нужны **особые флаги**:

```makefile
parser.o: parser.c parser.h
	$(CC) $(CFLAGS) -Wno-unused-parameter -c $< -o $@
```

Или особый `CPPFLAGS`:

```makefile
parser.o: CPPFLAGS += -DPARSER_DEBUG
parser.o: parser.c parser.h
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@
```

#### Промежуточные файлы `.i` и `.s`

`gcc -c` их создаёт во временном каталоге и удаляет. Если хотите их сохранить (для изучения или отладки), используйте `-save-temps`:

```bash
gcc -c -save-temps main.c -o main.o
ls
# main.c main.i main.s main.o main.o.original
```

Либо явные правила — это учебный вариант, на практике достаточно `gcc -c`.

```makefile
%.i: %.c
	$(CC) $(CPPFLAGS) -E $< -o $@
%.s: %.i
	$(CC) $(CFLAGS) -S $< -o $@
%.o: %.s
	$(AS) $< -o $@
```

#### Линковка

Собирает все объектные файлы в один исполняемый файл, где:
- все секции `.o`-файлов слиты воедино;
- **все неразрешённые ссылки разрешены** (либо адресами внутри файла, либо через динамический линковщик);
- есть точка входа (`_start`), которая вызывает `main`;
- подключены стартовые файлы (`crt1.o`, `crti.o`, `crtn.o`) и стандартная библиотека C.

Правило линковки обычно одно на весь makefile:

```makefile
$(TARGET): $(OBJS)
	$(CC) $(LDFLAGS) $^ -o $@ $(LDLIBS)
```

- `s21_cat` — цель, имя итогового файла;
- `$(OBJS)` — зависимости (все `.o`);
- `$^` — все зависимости (`main.o util.o parser.o`);
- `$@` — имя цели (`s21_cat`);
- `$(LDFLAGS)` — флаги линковщика (`-L`, `-static`, `-Wl,...`);
- `$(LDLIBS)` — библиотеки (`-lm`, `-lpthread`), **после** объектников.
##### Линковка статических и динамических библиотек

[[Сборка программы#Статические и динамические библиотеки|Статические и динамические библиотеки]]

**Динамическая** (по умолчанию):
```makefile
LDLIBS = -lm -lpthread
```

В бинарник попадает только «заглушка», сама библиотека подгружается при запуске. Требует наличия `.so` в системе (или `-Wl,-rpath`).

**Статическая:**
```makefile
LDFLAGS = -static
```

Всё вшивается в бинарник, он становится больше, но не зависит от системных `.so`. Часто используют в учебных проектах (School 21 и т.п.), чтобы бинарник запускался везде.

**Своя библиотека в нестандартном месте:**
```makefile
LDFLAGS = -L/opt/mylib/lib -Wl,-rpath,/opt/mylib/lib
LDLIBS  = -lmylib
```

- `-L` — где искать `libmylib.so`;
- `-Wl,-rpath,...` — чтобы при запуске не нужен был `LD_LIBRARY_PATH`;
- `-lmylib` — сама библиотека (файл `libmylib.so` или `libmylib.a`).

##### Порядок аргументов при линковке

Важно: **объектники → `LDFLAGS` → `-o` → `LDLIBS`**. Линковщик разрешает символы слева направо: библиотека должна идти **после** объектников, которые её используют, иначе `undefined reference`.

```makefile
$(CC) $(LDFLAGS) $^ -o $@ $(LDLIBS)
#     флаги      .o   выход  библиотеки
```
### Фиктивные цели (phony targets)

Это «кнопки» для запуска действий. Они не создают файлов и должны быть объявлены через `.PHONY`.

```makefile
.PHONY: all clean

all: s21_cat

clean:
	rm -f s21_cat $(OBJS)
```

`make` по умолчанию считает имя цели именем файла. Если в каталоге случайно появится файл `clean`, `make clean` скажет `'clean' is up to date` и **ничего не удалит**. `.PHONY`отключает проверку существования файла.

#### `all` — цель по умолчанию

```makefile
.PHONY: all
all: s21_cat
```

Агрегирует сборку. `make` без аргументов запускает **первую цель** в файле — обычно это `all`. Позволяет позже расширить:

```makefile

all: s21_cat docs tests
```

Рецепта у `all` нет: она просто требует, чтобы зависимости были готовы.

---
#### `clean` — удаление артефактов

```makefile

.PHONY: clean
clean:
	rm -f s21_cat $(OBJS) $(DEPS)
```

Всегда выполняет `rm`, даже если файл `clean` существует. Должна удалять **все** артефакты, включая `.d`-файлы при `-MMD`

---
#### `re` / `rebuild` — пересборка с нуля

```makefile

.PHONY: re
re: clean all
```

Удобный ярлык: `make re` = `make clean && make`. Зависимости выполняются по порядку: сначала `clean`, потом `all` (потому что `clean` — фиктивная и всегда «выполняется», а `all`после неё пересоберёт всё заново).

---
#### `test` — запуск тестов

```makefile

.PHONY: test
test: s21_cat
	./tests/run.sh
```

Зависимость `s21_cat` гарантирует, что бинарник собран до запуска тестов.

---
#### `fmt` / `lint` — форматирование и проверки

```makefile

.PHONY: fmt lint
fmt:
	clang-format -i $(SRCS) $(wildcard *.h)
lint:
	cppcheck --enable=all $(SRCS)
```

## Работа с подкаталогами

## Автогенерация зависимостей

Флаги `-MMD` и `-MP` **флаги генерации зависимостей GCC** (не самого `make`). Когда вы компилируете `main.c`с этими флагами, GCC **попутно** генерирует файл `main.d`, содержащий правило для `make` со списком всех заголовков, от которых зависит `main.c`

Содержимое `main.d` выглядит примерно так:

```makefile
main.o: main.c util.h config.h
```

**Особенности:**
- **`.d`-файлы не удаляются автоматически.** Их нужно явно добавить в `clean`:
```makefile
clean:
	rm -f $(TARGET) $(OBJS) $(DEPS)
```

- В конце файла нужно добавить директиву GNU Make: `-include` с указанием на подключаемые файлы

```makefile
CC       = gcc
CPPFLAGS =
CFLAGS   = -Wall -Wextra -g -MMD -MP
LDFLAGS  =
LDLIBS   =

SRCS     = main.c util.c parser.c
OBJS     = $(SRCS:.c=.o)
DEPS     = $(OBJS:.o=.d)
TARGET   = prog

.PHONY: all clean re

#  Цели
all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(LDFLAGS) $^ -o $@ $(LDLIBS)

%.o: %.c
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

clean:
	rm -f $(TARGET) $(OBJS) $(DEPS)

re: clean all

# ============================================================
#  Директива для подключения .d файлов с зависимостями
# ============================================================
-include $(DEPS)
```

## Директивы make

### `include` и `-include`

`-include` — это **не команда shell** и **не опция GCC**. Это директива самого `make`, которая обрабатывается **на этапе чтения Makefile**, до выполнения любых рецептов. Она буквально вставляет содержимое указанных файлов в то место, где стоит.

>Отличие `-include` от `include`: первая не вызовет никаких ошибок, если указанного файла пока ещё не существует (полезно, при автогенерации зависимостей через флаги `-MMD` и `-MP`)

Содержимое `main.d` выглядит так:

```makefile
main.o: main.c util.h parser.h
util.h:
parser.h:
```

Когда `-include` его подключает, эти строки становятся **частью вашего Makefile** — как будто вы сами их написали. С этого момента `make` знает: «`main.o` зависит от `util.h` и `parser.h`». Дальше работает обычная логика проверки временных меток.

## Примеры

```makefile
CC       = gcc
CPPFLAGS =
CFLAGS   = -Wall -Wextra -g -MMD -MP
LDFLAGS  =
LDLIBS   = -lm

SRCS     = main.c util.c parser.c
OBJS     = $(SRCS:.c=.o)
DEPS     = $(OBJS:.o=.d)
TARGET   = s21_cat

.PHONY: all clean re
.DEFAULT_GOAL := all
.DELETE_ON_ERROR:

# --- уровень 3 ---
all: $(TARGET)

$(TARGET): $(OBJS)
	$(CC) $(LDFLAGS) $^ -o $@ $(LDLIBS)

# --- уровень 2 ---
%.o: %.c
	$(CC) $(CPPFLAGS) $(CFLAGS) -c $< -o $@

# --- фиктивные ---
clean:
	rm -f $(TARGET) $(OBJS) $(DEPS)

re: clean all

-include $(DEPS)
```
